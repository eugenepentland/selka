# Compiler behavior specification

This document records implemented behavior with executable Zig regression evidence.
Each stable ID has one primary `// spec:` test. Additional tests and Python
acceptance drivers exercise further cases; these links are not a claim of exhaustive
coverage or proof of memory safety. The language remains experimental. The QBE
native backend is the only runtime: every behavior below is native behavior, and
bytecode names the internal IR it consumes rather than anything that is executed.
The roadmap in `docs/experiments/roadmap.md` tracks unsupported and planned features.

## Core semantics

- [BYTE-LITERAL-1] Quoted byte literals produce ordinary fixed `[N]u8` arrays without terminators. UTF-8 source contributes its encoded bytes; escapes are `\n`, `\r`, `\t`, `\0`, `\\`, `\"` and exactly two hexadecimal digits after `\x`. Empty literals have length zero; each literal is limited to 65,536 decoded bytes (`E_BYTE_LITERAL_LIMIT`). Checking, generic bodies, module relocation, cached syntax and formatting preserve ordinary array identity and behavior. Invalid escapes and unterminated literals are located source errors.

- [CORE-1] Evaluates multiplication before addition, honors parentheses, and associates subtraction from the left.
- [CORE-2] Reports checked arithmetic overflow at the responsible operator without evaluating arithmetic during checking.
- [CORE-3] Returns located source diagnostics for empty input, malformed syntax, and out-of-range integer literals.
- [CORE-4] Accepts the signed and unsigned integer width limits and rejects literals above each maximum.
- [CORE-5] Constructs records by field name and preserves original values when producing updated record copies.
- [RECORD-DEFAULT-1] A record field may declare an immutable scalar default after `=`; a constructor call may omit that field and the default is materialized, positional and named construction stay in declaration order, and a required field after a defaulted one rejects like a function parameter. Enum-keyed tables keep requiring every key.
- [RECORD-UPDATE-1] `replace(record, field=value, …)` returns a copy of the record with only the named fields changed and every other field preserved; the base evaluates before the values, the result is a fresh record value, and the positional `replace(list, index, value)` intrinsic is unchanged.
- [CORE-6] Preserves fixed-array copies and accepts each integer index width, including zero-length arrays.
- [CORE-7] Rejects interchange between distinct nominal domains and requires their declared construction operations.
- [DOMAIN-EQUALITY-1] Values of the same scalar domain support == and != by their integer or boolean backing values, including generic equality requirements. Declaration identity must match across module aliases; equality exposes no backing value, permits no implicit arithmetic or ordering, evaluates operands left to right, and preserves VM cleanup and execution limits.
- [CORE-8] Rejects nonexhaustive matches after a variant is added, including matches on statically known values.
- [CORE-9] Uses enum case names for table construction and indexing regardless of declaration or initializer order.
- [CORE-10] Rejects silent result abandonment and permits `_ = value` to release the result obligation explicitly. A diagnostic about a binding that cannot be assigned or modified names that rule rather than a declaration keyword.
- [CORE-11] Unwraps successful results and propagates compatible error payloads by case name across nominal result types. Native propagation constructs the outgoing result before releasing unfinished operands; failed construction releases the propagated payload before those operands.
- [TRY-CONVERT-1] `?` propagating a result whose error type is the payload of a case of the enclosing function's error union converts implicitly: the error value is wrapped in that case, the outgoing tag is the case's tag, and a payload type that is not a case of the enclosing union still rejects with a located type error.
## Ownership and capabilities

- [OWN-9] Releases previously acquired resources exactly once when a later acquisition propagates an error.
- [OWN-10] Delegates environment access through explicit grants and distinguishes missing, empty, and present values.
- [OWN-11] Rejects direct and transitive allocation that violates declared effect bounds and reports a call witness.
## Projects and native output

- [QBE-PROLOGUE-1] Generated code tests a trap by loading `ctx->trap` through a prologue address instead of calling `myl_qbe_failed`, and a function emits the heap pointer, the root mark and the root restore only when one of its instructions has an opcode that can allocate. A rooted function whose opcodes cannot allocate at all — no call, no allocation — pushes no roots and carries none of that prologue, while its locals stay reachable because no collection can run while it executes. An unused heap pointer is dropped after emission. Which rooted instructions actually push is refined by `QBE-SAFEPOINT-1`.
- [QBE-SAFEPOINT-1] A rooted instruction pushes the live roots only when its own lowered body can call something that allocates: an opcode that admits allocation in one variant but not the one being lowered — a byte-string element read, a scalar widening cast, a checked `+` — runs with no root push and no root restore around it, because its text names no allocating callee. Every guest call, collection constructor, print sink and provider read still pushes, so no value reachable at a collection point becomes unreachable, and trap behavior, results and collection timing are unchanged.
- [QBE-PURECALL-1] A direct guest call pushes roots only when the callee can allocate, directly or transitively: a function whose emitted body reaches no allocating call — an integer predicate, a cursor advance, a field access — is called with the root chain left as the caller found it, and a call to a function that can allocate still roots every live local and operand. The call graph is read from the same emitted text the safepoint decision uses, so an analysis answer cannot drift from the lowering it describes, and every call that can collect keeps its roots.
- [QBE-ROOTINLINE-1] Generated code links and restores the root chain with straight-line IL instead of calling `myl_native_root_push` and `myl_qbe_root_restore`: at each safepoint it loads the heap's root head once through the frozen offset of `myl_native_heap.roots`, then per live root stores the previous head, the traced address and the type descriptor into that root's 24-byte slot and links the slot into that same head field, and the restore stores the frame's mark back into it. The slot layout matches `struct myl_native_root` field for field, the offset is frozen by a matching `_Static_assert` in `src/qbe_runtime.c`, and the two runtime helpers remain for the C side even though no generated call site names them, so roots, collection timing and results are unchanged.
- [QBE-PROMOTE-1] A function declares its scalar local and operand slots in the entry block, before any label the frame protocol introduces, because QBE promotes a slot to a temporary only when its `alloc8` sits there; per-pc aggregate scratch stays after the protocol so a zero-length aggregate is never folded to a null load, and a slot declaration no instruction reads is removed after emission. Observable behavior — values, traps, traces and exit status — is unchanged; the generated code calls no runtime helper and only promotes what QBE can prove is a uniform load/store slot.
- [QBE-FRAMES-1] Each generated guest function owns one frame record in its own native stack — `prev`, its function metadata and its position — links it with two stores and unlinks it on every return path, so entering and leaving a frame is straight-line code rather than two runtime calls. The prologue enforces the logical `--max-frames` ceiling and the execution stack floor with inline compares whose cold path raises `R_FRAME_LIMIT` through `myl_qbe_fail_frame`. Trap traces are the `prev` chain innermost-first, `omitted_frames` still counts the depth beyond the first sixteen, and `--max-frames`, trace text, and the bounded guest stack are unchanged.
- [QBE-POSITION-1] A build without step accounting stores a frame position only where a diagnostic can read it: an instruction whose body can reach a failure path, an `assert`, or a call site keeps its `storel <pc>, %position`, and every instruction that cannot fail and calls nothing omits it, leaving the previous observed position in place. Trap traces, `assert` messages and their source locations are unchanged; a build with step accounting keeps every position because every instruction can then exhaust the budget.
- [QBE-STEP-ACCOUNTING-1] Instruction step accounting is build policy: a Debug build, a shared library, and a `run` that named `--max-steps=N` keep the exact per-instruction position marker and step check, while a ReleaseFast executable whose build arguments name no ceiling omits the budget check and its `max_steps` metadata (keeping the per-instruction position marker that trap traces and `assert` messages read), so `mylang run` without `--max-steps` and `mylang build --mode ReleaseFast` compile straight-line code. Such a binary reports `R_NO_STEP_ACCOUNTING`, naming how to get a bounded run, when the runtime is given `--max-steps=`, instead of silently ignoring the ceiling; `--max-frames`, `--timeout` and `--max-memory` stay runtime-enforced and unaffected.
- [QBE-BLOCKS-1] Straight-line instructions share one basic block: an instruction falls through into its successor's body, and an instruction label is emitted only when a branch names it, so locals cross instruction boundaries in registers instead of round-tripping through their slots. Step accounting, trap positions, program results and every other observable behavior are unchanged.
- [QBE-INTOPS-1] Checked integer multiplication, truncating and flooring division and remainder, shifts, and unary negation lower to inline QBE instructions with the same cold trap paths the runtime helpers used: an overflow reports `myl_qbe_fail_overflow_op` with the evaluated operands and width, division by zero reports `myl_qbe_fail_division`, and an out-of-range shift count or a negated minimum still calls the runtime helper, so trap codes, trap text, structured detail, sticky first-trap behavior and results are byte-identical to the call-based lowering.
- [QBE-FLOAT-ENV-1] The process floating-point environment is verified once, before guest code runs and again after every C FFI call returns, instead of on every floating operation: binary64 arithmetic and comparisons lower to bare inline QBE `add`/`sub`/`mul`/`div`/`ceqd`/`cltd`/`cled` with the same NaN canonicalisation, and the unary and conversion helpers no longer re-probe the environment. A context whose rounding mode is not round-to-nearest, or whose subnormal product behavior differs, traps `R_FLOAT_ENVIRONMENT` before the guest entry point executes, and a foreign call that changes the environment re-arms the same sticky trap before its result is used, so trap codes, trap text, sticky first-trap behavior and every result bit are unchanged.
- [QBE-LITERAL-1] A `str` or `bytes` literal whose every element is a constant scalar push is published once as an immortal image object instead of being constructed on every evaluation: the managed lowering emits a marker carrying the element descriptor, width, count and native payload bytes, the metadata unit turns each distinct marker into one C data block holding the managed object header, the list header and the element storage the runtime constructor would have written, and the lowered code loads the shared payload pointer. The data symbol hashes the element descriptor and payload, so equal literals share one object across every unit. Frozen objects carry the immortal header flag and arena region 0: the collector never queues, re-traces, frees or bulk-releases them, explicit release refuses them, and arena ownership checks treat them as heap-owned, so they survive `--gc-stress`, `with arena()` scopes and teardown. Content, type, length, indexing and equality are byte-identical to a constructed value, and the lowered body names no allocating callee, so a function whose only allocatable opcode is such a literal pushes no roots.
- [QBE-1] Emits deterministic independent QBE native function units with stable symbols and body-local instructions; unrelated body edits and declaration reordering preserve unchanged units. Unsupported native features fail before publishing output.
- [QBE-2] Builds Linux x86-64 executables and shared libraries directly through the Zig CLI without Python or a compiler source checkout; bundled runtime inputs, verified object reuse, source diagnostics, and native API adapters preserve native build behavior. The generated entry adapter and each guest function are separately cached objects, the fixed runtime translation units are archived once per build environment and linked after every object that can reference them, and section-level collection drops runtime a program never reaches. A stored object or archive is reused only when a fingerprint over its length and contents matches, so damaged bytes or a damaged fingerprint rebuild that one entry; an unchanged executable is republished by comparing length and then bytes, retaining its inode and modification time. `--run` executes a temporary native binary with inherited I/O and propagated status, then removes it while retaining cached objects. Shared-library links also bind the library's own data-descriptor symbols internally, so a guest object's non-PIC references resolve within the library instead of failing as preemptible relocations.
- [NATIVE-BUILD-RECLAIM-1] A native build owns its filesystem and process scratch in a reclaiming arena freed when the build ends, over the general allocator rather than the process arena, so a long-lived host that rebuilds its guest on every reload does not accumulate build memory.
- [NATIVE-STAGING-1] Every native build stages private scratch beneath one hidden `.pending/` folder in its destination directory and removes only its own child plus that folder when empty, so concurrent builders and interrupted runs leave at most one contained folder instead of one `.pending-<hex>` sibling per invocation.
- [QBE-HOST-COMPILER-1] A native build emits its guest's QBE units through its own executable by default (`/proc/self/exe emit-project-qbe`); `MYLANG_HOST_COMPILER` overrides that frontend with an explicit compiler, which a host application driven from a binary that is not itself a compiler supplies. `MYLANG_QBE` and `MYLANG_ZIG` likewise name the native tools when neither a flag, a tool beside the compiler, nor `PATH` locates them.
- [QBE-TRAP-DETAIL-1] Native traps carry a bounded, versioned structured detail captured from values the failing operation already evaluated: original index and receiver length for bounds failures (negative indexes preserved), and evaluated operands/width for division and checked overflow. Text and structured JSON render from the same detail; the JSON path does not reparse text. Native children emit one bounded `\x1eMYLANG-TRAP ` + JSON record on stderr while ordinary stdout, diagnostics, exit statuses, trap codes, locations, call stacks, omitted-frame counts and first-trap stickiness are preserved, and budget/host failures remain detail-free.

- [QBE-3] The compiler bundles only the native runtime build inputs — its runtime C sources and headers and the Zig runtime units it compiles, with their reference closure — never compiler tests or guest fixtures. A build materializes that tree once per build-time content hash, staging into a private directory and renaming so concurrent builds sharing a location never observe a partial tree, and reuses it on every later build. An explicit `--cache-dir` keeps the tree hermetically under `<cache-dir>/runtime/<hash>`; a default build instead shares a user-level location (`$XDG_CACHE_HOME/mylang/runtime/<hash>`, else `$HOME/.cache/mylang/runtime/<hash>`) so a fresh project reuses a tree another project already derived; it uses the per-project cache when neither variable names an absolute home, and also falls back to the per-project cache when the shared location cannot be written (for example a read-only home directory).
- [QBE-RUNTIME-INSTALLED-1] `zig build` prebuilds the runtime archive and text-formatter object for each optimize mode and installs them beside the compiler under `lib/mylang-runtime`, each named by a portable hash of the runtime content hash, pinned Zig version, mode and target. A `mylang build` links a matching installed artifact directly — skipping the runtime compile on a cold build — and reports `runtime_installed`; a removed, cross-target, mode-mismatched or corrupted install (its fingerprint no longer matching the `.digest` beside it) falls back to compiling the runtime from source. The portable hash excludes tool file stamps, so an installed archive matches a build that resolved its tools from a different path.
- [QBE-4] Native builds identify their inputs without rereading them: the compiler's own identity is a build-time digest of its sources, the Zig toolchain and the optimize mode, and external tools are identified by path, size and modification time. Object-cache keys still change when the native build driver, runtime, tools, target or mode change; an ordinary compiler edit that cannot change how emitted IL becomes an object does not move them (see `QBE-DRIVER-IDENTITY-1`). Build tools resolve from an explicit option, then beside the compiler's own executable, then `PATH`; the working directory never selects one.
- [BUILD-MODE-1] A native build that names no `--mode` builds `ReleaseFast`, because `mylang build` and `mylang run` are asked for a fast program; `--mode Debug` selects the unoptimized build explicitly and `--mode` still rejects any other spelling. The chosen mode is what the build usage text advertises, what `--report` states, and what the object cache, the runtime install and the run identity key on, so switching modes never reuses another mode's objects. A guest test run keeps its own `Debug` default, which `mylang test --mode ReleaseFast` overrides.
- [QBE-RUNTIME-MERGE-1] The fixed runtime translation units compile into the archive's single member through one `zig build-obj` invocation naming every source, so a cold build pays one toolchain start rather than one per unit. The relocatable merge keeps each unit compiled with function and data sections, so the final `--gc-sections` link still drops runtime a program never reaches.
- [QBE-STRIP-1] Native output carries no debug information: every C compile and assembly passes `-g0`, the Zig runtime unit is built with `-fstrip`, and the link strips the symbol table, so a cached object, a runtime archive and a published executable hold only the code and data the program runs. Native traps, their frames and their structured detail come from the runtime's own tables, so a stripped program reports exactly what an unstripped one did.
- [QBE-GENERATION-1] A cache root keeps one live generation per artifact family: objects under `objects/<hash>`, `mylang run` programs under `run/<hash>` and the Zig test suites' guest executables under `exe/<hash>`, each named by the native driver identity and the bundled runtime hash. Tool stamps, mode and target stay in each entry's key but not in the generation, so every process of one compiler build shares one generation whatever path it resolved its tools from or mode it asked for, and never evicts a concurrent sibling's entries. Opening a generation removes every sibling generation in that family that no process still leases, so a changed driver or runtime never leaves its predecessors' artifacts behind; an existing generation is reused without a sweep, the shared staging folder is never swept, and eviction is best effort so a cache that cannot be swept still serves the generation it keeps.
- [NATIVE-GENERATION-LEASE-1] Every process that opens a generation directory for use holds a shared advisory lock on a `.lease` file inside it for the rest of its life, and a sweeper takes a non-blocking exclusive lock on each sibling's lease before evicting it and skips whatever it cannot take. Concurrent builds under one cache root — the compiler and the host applications, whose driver identities differ — therefore never delete a generation another process is still compiling or linking into. Leasing is advisory and best effort: an entry with no lease file is still swept, a filesystem that cannot lock behaves as before, and the kernel releases a dead process's lease, so no abandoned lease pins a generation and no wall clock is consulted.
- [NATIVE-PUBLISH-REPAIR-1] Publication into a generation heals a lost eviction race instead of failing it: a rename that reports the destination missing recreates and re-leases the generation directory and retries once, and a link whose cached input objects are no longer on disk rebuilds them into a restored generation and retries the link once. A link that fails with every input present is the program's own error and is reported unchanged.
- [QBE-DRIVER-IDENTITY-1] The object and executable caches key on a *native driver identity* — a build-time digest over the native build driver and link-policy sources (`src/qbe_build*.zig`, `src/native_link*.zig`), the Zig version and the optimize mode — rather than the whole compiler identity. Objects are already content addressed by the QBE IL the frontend emitted, the runtime sources by the bundled content hash, the tools by their stamps and the link flags by the cache contract, so a frontend or checker edit that cannot change how IL becomes an object no longer evicts every cached guest object and executable. The compiler identity is unchanged and still keys frontend/semantic caches and `mylang test` result reuse.

- [EXPORT-PLACEMENT-1] A re-export `export module.Name;` naming an imported declaration may appear anywhere among top-level declarations after the module/import header. Discovery collects directives in source order with original locations; a duplicate or unknown re-export and private interface leaks still reject. The bare `export Name;` directive is removed and rejects with `E_EXPORT_REMOVED` (see `PUBLIC-DECL-3`). Directives inside function or type bodies reject, and formatting preserves directive order and comments.
- [PUBLIC-DECL-2] `list-declarations` reports a `public` declaration's `exported` flag as true while its `exports` array stays empty, and the declaration's byte range begins at the `public` modifier so a rename round-trips exactly.
- [PUBLIC-DECL-3] The bare `export NAME` directive is removed: it rejects with `E_EXPORT_REMOVED` at the directive, both in `list-declarations` and when a project is checked. Only the dotted `export module.Name` re-export, which publishes an imported declaration, remains an export directive.
- [REEXPORT-1] An export directive may name an imported declaration (`export shared.units.Distance`) as well as a local one. The facade module publishes that declaration under its own local name; a reference through the facade resolves to the defining module's identity with the target's own export privacy enforced, and interfaces, contracts and the project fingerprint report the facade name while the schema uses the defining declaration.
- [PUBLIC-DECL-1] A top-level declaration is published with a leading `public` modifier (`public def`, `public host def`, `public extern def`, `public record`, `public class`, `public enum`, `public union`, `public result`, `public domain`, `public resource`, `public type`, `public const`, `public constraint`). The modifier replaces the bare `export NAME` directive, so a module's published surface is written on the declarations themselves and `list-declarations` reports each declaration's export flag with an empty directive list.
- [REEXPORT-2] An export directive naming a qualified path whose alias is not imported, or whose target is not exported in its defining module, rejects with the existing located E_UNKNOWN_EXPORT/E_PRIVATE_SYMBOL family. list-declarations reports the facade directive with its alias and leaves local declaration flags unchanged.

- [PROJ-1] Loads shared module dependencies once in dependency order and releases state on allocation failure.
- [PROJ-2] Reports module cycles with both the importing location and the related source location.
- [PROJ-3] Rejects duplicate exports, missing exported symbols, private types exposed through public interfaces, and a re-export whose qualifier names no import or whose target is not exported in its defining module.
- [PROJ-4] Reports related declarations in their original source files after project source mapping.
- [PROJ-5] `mylang run FILE` loads the reachable project graph when the entry file opens with a `module` header or a module-only `import`/`export` directive, so a single file that imports a standard module needs no separate command; a file with no module header stays one standalone unit, and `run-project` remains the explicit project-entry alias.

- [PROJ-6] Project loading defaults to 4,096 reachable modules and 65,536 import edges, up from 256 and 4,096; a `mylang.json` `budgets` object overrides `max_modules`, `max_imports`, `max_file_bytes` and `max_total_bytes`. Each present value must be a positive integer, unknown and duplicate budget keys are rejected like every other configuration field, and an absent field keeps its default.
- [PROJ-7] `mylang build FILE` detects a module-project entry the same way `run` does and links the reachable graph without requiring `--project`; a plain single-file program keeps the one-unit path, and `--project` remains an explicit override.
## Discovery and formatting

- [TOOL-1] Groups exact duplicate bodies after binding renaming while preserving resolved binding identity.
- [TOOL-2] Reports literal differences once per exact-group representative when discovering near duplicates.
- [TOOL-3] Reports incomplete near-duplicate discovery when work budgets are exhausted and rejects invalid budgets.
- [TOOL-5] `fmt` prints the one canonical layout to stdout, permits semantically incomplete drafts but rejects syntactically invalid input, and `--check` is nonzero when the input bytes differ from canonical output. The fixed layout uses four-space suites; one space around binary/assignment operators and after commas and annotation colons; no padding inside ordinary delimiters; no trailing whitespace; one final newline for nonempty source; two blank lines between top-level declarations and one after the header directive group. Comment attachment, literal values, directive order and expression evaluation order are preserved, and there is no configurable wrapping.
- [TOOL-6] Includes calls in untaken paths and cycles when calculating static function reachability.
## Evaluation and wire boundaries

- [WIRE-2] Rejects duplicate input names, keywords, unsupported input types, and noncanonical or out-of-range values.
- [WIRE-3] Encodes independently constructed typed values without consuming them and enforces byte, value, and depth limits.
- [WIRE-4] Rejects duplicate, missing, unknown, and private function entries in domain codec declarations.
## Command line

- [DECLARATION-LIST-1] `list-declarations` prints one parse-only `declarations-v1` JSON document with the declared module name or null for a single-file program, its import names and explicit aliases, its export directives (a re-export carries its qualifier as `alias`), and every top-level declaration's kind, name, export flag, byte range and attached comment start. The kinds are exactly the top-level constructs the parser accepts: alias, const, struct, enum, union, result, domain, resource, fn and host_fn. An export directive sets the named local declaration's flag, a re-export marks no local declaration, and unknown and duplicate export directives reject with the existing located diagnostics. Listing requires only parsing, so modules with type or ownership errors still list, and no name resolution, checking or execution is claimed.
- [INTERFACE-SIGNATURE-1] `list-interfaces` prints each exported callable's whole signature by default: parameters in their Python type spelling (capabilities as `Filesystem`, `Network`, `Clock`, `Entropy`, `Environment`, never the removed `*_cap` internal names), the inferred `effects(...)` set when the body checks, `mutates(...)` by parameter name, and the declared ceiling when the source wrote one. A body that fails to check leaves the declaration listed and reports no body diagnostic, so the interface gate stays declaration-only. `--contracts` renders the same Python capability spellings in its canonical signature text.
- [INTERFACE-SIGNATURE-CLI-1] The `list-interfaces` command renders a capability entry parameter as its Python spelling (`Filesystem`, `Clock`) rather than the removed internal tag, including for a single-file program that exports `main`.

- [DECLARATION-LIST-2] Listed byte ranges are zero-based, half-open, disjoint and ordered by start. A declaration runs from its first token through its terminating semicolon or final token before an implicit newline/EOF terminator, and its comment start covers contiguous leading `#` lines with no blank line before the declaration. The module header, import statements, export directives and comment-and-declaration ranges account for every byte of the file except whitespace and line comments between them.

- [DEPENDENCIES-1] `project-dependencies` emits a versioned checked module graph with resolved imports, source byte hashes, implementation identity and exact consumed generated-input manifest hashes. It does not execute guest code; invalid projects emit no complete receipt.

- [DISK-PROJECT-1] Interpreter application hosts load `main.my` and imported modules from an explicit disk directory, with bounded reads and no embedded-source fallback. Failed loads and compilation release owned storage and preserve located source errors; a later invocation reads repaired source. Existing typed host registrations remain mandatory. The standalone acceptance driver also changes guest source and project roots using the same executable without Zig or Guardian on PATH.

- [CLI-1] Distinguishes source errors, runtime traps, and invalid command usage through actual process results.
- [ARGV-1] A guest entry point may take `args: list[str]` as its first parameter; `mylang run` and `build --run` reserve their own options before `--` and pass every value after it as guest arguments, installed executables pass OS arguments after `argv[0]`, and generated native entry points build the same managed list with validated UTF-8 text.
- [CHECK-PROJECT-ENTRY-1] `mylang check ENTRY` where ENTRY opens as a module project checks the reachable project graph exactly like `check-project`, executing nothing; a plain single-file program keeps the one-unit path unchanged.
- [EPRINT-1] `eprint` is the standard-error spelling of `print`: it accepts the same values and `sep=`/`end=` keywords, writes only stderr, contributes the same `output` effect, and shares the buffered one-line native output path without mixing bytes between streams.
- [STREAM-CAPABILITY-1] `Stream` is a capability passed like `Filesystem`. The entry point may declare `out: Stream` and `err: Stream`; the entry rule matches Stream parameters by name, admits at most one of each, and rejects any other name with `E_MAIN`. `stream.print(values..., sep=, end=)` renders like the old printing builtin and `stream.write(text) -> int` writes the text and returns its character count; both contribute the `output` effect and take the destination from the receiver value, so a helper declared `def show(log: Stream)` may be handed either `out` or `err`. Streams are granted unconditionally, including under `--restrict`, and the per-type native renderers write through the stream's own sentinel. A bare `print`/`eprint` reports `E_OUTPUT_CAPABILITY` with the fix to add `out: Stream` and pass one from main; a local binding or declared function named `print` still shadows the spelling.
- [DEBUG-LINE-1] `debug(values...)` renders like `print` to standard error, takes no capability, contributes no effect, returns unit, and is emitted only by Debug builds and by `run`/`test`; a debug line therefore never changes a signature or a checked effect bound.
- [RESULT-MAIN-1] A guest `main` may return `Result[int, str]`: `Ok(code)` becomes the process status `code & 0xFF`, while `Err(message)` writes exactly one `message` line to stderr and exits 1; runtime traps and source/usage failures keep their existing distinct statuses.
- [OPTION-TRY-1] `?` propagates `None` only within a function returning a compatible `Option[T]`; a `Some(value)` unwraps to `value`, and mixing `Option` propagation with a result-returning function or vice versa is a located type error.
- [BOUNDARY-CLI-1] `examples/boundary-cli` is a two-module acceptance program that combines `args: list[str]`, `Filesystem`, explicit `Environment`, `print`, `eprint`, source-file reads, and `main -> Result[int, str]`, and the same cases pass through `run`, `build --run`, and an installed executable.
- [CAPABILITY-METHOD-NARROWING-1] `fs.read_only() -> Filesystem` narrows a `Filesystem` capability to read authority by intersecting its permission mask. The derived capability is an ordinary typed value: it can be passed, returned, stored in records/classes, and cannot be stored in a list or `Cell`. It performs no I/O and contributes no effect.
- [CAPABILITY-METHOD-NARROWING-2] `restrict_resource[...]` is removed and reports `E_REMOVED_SPELLING` naming `fs.read_only()`; `acquire_resource`, `complete_resource`, `read_resource` and `write_resource` are unchanged; `environment_get[...]` is now a trusted standard-library spelling only.
- [FILESYSTEM-DIR-1] `fs.dir(path) -> Filesystem` derives a filesystem rooted at the string-literal `path`, resolved under the receiver's root. It records the scope lazily in a bounded host-side table, performs no I/O, and contributes no effect. Every acquisition through the derived capability joins the prefix and rejects a request that could leave the root (`..`, `.`, empty components, backslashes or NUL); `restrict_resource` preserves the scope. A dynamic path or a literal that escapes the root is `E_FILESYSTEM_DIR` at check time, and a non-`Filesystem` receiver is rejected.
- [FILE-METHOD-1] Every whole-path file helper also accepts a qualified method spelling on a `Filesystem` value: `fs.open(path, mode)`, `fs.read_text(path)`, `fs.write_text(path, text)`, `fs.read_file(path)`, `fs.write_file(path, data)`, `fs.exists(path)`, `fs.listdir(path)`, `fs.mkdir(path)` and `fs.remove(path)`. The receiver is the capability operand, so the method form has one fewer argument than the free spelling, and both share the same arities, result types, `E_ARITY`, the literal-mode `E_FILE_ARGUMENT` rule and the trapping `with fs.open(...) as f:` head. The method belongs to the receiver, so a declared function or local named `read_text` still claims the free `read_text(fs, path)` spelling, and generic bodies keep rejecting the file builtins under either spelling.
- [NETWORK-HOST-1] `net.host(name) -> Network` narrows a `Network` capability to the single string-literal endpoint `name`. It records the scope lazily in the same bounded host-side table as `fs.dir`, performs no I/O, and contributes no effect. Every acquisition through the derived capability requests exactly the recorded endpoint, so a narrowed `Network` composes with a `connect` wrapper that takes no request string; an endpoint outside the active `--allow-endpoint` grant is still denied. Re-narrowing to a different endpoint traps `R_CAPABILITY`. A dynamic, empty or NUL-bearing name is `E_NETWORK_HOST` at check time, and the receiver must be a local `Network`.
- [NETWORK-ENDPOINT-1] `mylang run`, `run-project` and `build --run` accept a repeatable `--allow-endpoint=IP:PORT` grant for a `Network` entry point under `--restrict`. The endpoint is a literal numeric IPv4 address with a nonzero port; a DNS name, an IPv6 literal, an empty value and a repeat are usage errors. The grant provisions the native scoped network provider, whose allowlist matches the request verbatim (no DNS resolution or redirect following) and dials it only on an allowed acquisition; `--allow-all` grants every literal endpoint. Without the grant, `--restrict` refuses the entry point before execution with `--allow-endpoint=IP:PORT` in the message, and an endpoint outside the grant fails as `Connected.err(2)` without opening a socket. A default invocation with no grant keeps the previous behavior: the network provider stays absent and network access is denied.
- [NETWORK-SURFACE-1] The `network` standard module wraps provider acquisition and I/O so a guest does not spell the raw builtins: `connect(net)` acquires a `Connection`, `read[const N](connection)` and `write[const N](connection, data)` transfer bytes, and `close(connection)` completes the handle. The wrappers return declared `result` types and contribute the `network` effect; because resources are linear, each wrapper consumes the connection it receives.
- [ENVIRONMENT-GET-1] On an `Environment` capability value, `env.get("NAME")` returns `Option[str]`: `Some(value)` decoded as UTF-8 for a value the provider exposes and `None` when the name is absent. The name must be a literal `str`, and a dynamic name is `E_ENVIRONMENT_NAME`. A name outside the active `--allow-env` allow-list is a denied authority and traps `R_CAPABILITY` rather than answering `None`. `environment_get[...]` is accepted only in embedded standard-library sources, like the `__float_sqrt` intrinsic.
- [ENVIRONMENT-ONLY-1] `env.only("HOME", "PATH") -> Environment` narrows an `Environment` to a literal tuple of names by intersecting it with the runtime `--allow-env` allow-list. It performs no I/O and contributes no effect, and the derived capability is an ordinary typed value. Only positional string literals are accepted; a dynamic, empty or NUL-bearing name is `E_ENVIRONMENT_NAME`.
- [ENVIRONMENT-NAMES-1] `env.names() -> list[str]` returns the visible environment names as a fresh sorted managed list, honouring both the `--allow-env` allow-list and any `env.only(...)` narrowing. It takes no arguments and contributes the `environment` effect.
- [MANAGED-CELL-1] `Cell[T]` is a managed one-field reference constructed as `Cell(value=...)`; `.value` reads and replacements are shared across aliases and function calls, scalar and managed copyable contents are supported under GC stress, result resources and capabilities are rejected, and Cell values have no equality or rendering spelling.
- [CELL-COLLECTION-1] `Cell[T]` is not a collection: prelude and generic collection operations such as `sorted`, indexing, membership and search reject it with located type diagnostics instead of assuming collection storage.
- [CELL-GENERIC-1] Generic bodies recognize both `Cell(value=value)` and `Cell[T](value=value)`, infer the element type where possible, and account for the constructor's `managed_allocation` effect even when the generic declaration is otherwise unused.
- [CELL-EQUALITY-1] Equality-dependent membership, search and removal operations reject list elements and nested value graphs that contain `Cell`, including `in`, `list.contains`, `list.index`, and `list.remove`.
- [VALUE-EQUALITY-1] Values of the same non-callback, non-Cell aggregate type support `==` and `!=`: plain records, fixed arrays, unions, `Result` and `Option` compare structurally, and a managed `class` compares by reference identity. Reference cycles compare by identity, so a self-referential graph never diverges. A type whose fields reach a callback, `Cell` or resource still rejects with `E_TYPE`, and equality keeps left-to-right evaluation and the existing execution limits.
- [EQUALITY-CONTEXT-1] The two operands of `==` and `!=` share one aggregate type, and an operand reached through a field access over a known value supplies that type to a contextual constructor on the other side exactly as a plain binding does, so `hold.opt == Some("x")`, `hold.opt == None` and `hold.kind == Kind.atom("x")` type-check without an intermediate local. A field access whose base type or field is not statically known supplies nothing, so `Some("x") == Some("x")` still reports `E_OPTION_INFERENCE`.
- [OPTION-TRY-2] Generic body checking propagates `Some(value)` and `None` through `?` when the enclosing function returns a compatible `Option[T]`, and rejects propagation into a result-returning function with a located diagnostic.
- [CAPABILITY-DIAG-1] When an entry point requests several ungranted capabilities under `--restrict`, `run`, `build --run`, and installed executables stop at the first failed grant and emit exactly one identical diagnostic.

- [INCREMENTAL-INTERFACE-1] The project interface fingerprint is composed from the sorted semantic interface fingerprints of exported interface items only, so exports follow exported constants, declared effect ceilings and parameter defaults while comments, formatting, source paths, spans and private declarations are excluded.

- [MUTATION-OVERLAP-1] The writable/read-only overlap obligation fires only when the callee declares a `mutates(...)` contract; an unannotated helper's inferred writes are not a contract, so forwarding two shared collections through it is accepted like Python, while a declared footprint called with possibly-aliasing read-only arguments still rejects `E_MUTATION_OVERLAP`.
- [MUTATION-METADATA-1] `effects(mutation)` names externally observable managed-state writes, and a signature may carry the optional `mutates(a, b)` clause after its effect ceiling; names normalize to sorted duplicate-free parameter positions, unknown names reject at the declaration, and the clause requires the mutation bit only when an effect ceiling is declared. Callable types may bind parameter names in the same clause without changing signature identity. The compiler records inferred write footprints, mutation write facts and a sound return-origin bound, preserves them through copying, relocation, generic substitution, callable identity, interface schemas and bytecode validation, rejects forged or missing IR summaries, and versions the serialized effect contract as `effects-v3` so older entries are never admitted. M1 records these facts only; alias, overlap and ordinary call-permission enforcement is the separate M2 guarantee.
- [W-MUTATES-MISSING-1] A function with no effect ceiling whose body writes storage reachable from a caller argument is diagnosed with a warning when its declaration omits `mutates(...)`; reference-typed `class` parameters are exempt, because writing through the reference is what the parameter is for, so only by-value inputs such as a `list`, array or `record` position demand the clause. The diagnostic prints the inferred clause verbatim so it can be pasted onto the declaration, listing every inferred parameter position by name. A `mutates(...)` clause without an effect ceiling means unbounded effects with that declared footprint, and an explicit ceiling that lacks `mutation` still rejects `E_MUTATES_EFFECT`. The warning is advisory for this version (ADR D7) and does not fail the build; a declared ceiling keeps the existing `E_MUTATION_PERMISSION` enforcement unchanged.
- [UNUSED-IMPORT-1] A direct `import` whose alias or dotted name no reference in its module resolves through is diagnosed as `W_UNUSED_IMPORT` at the imported name, beside `W_UNUSED_BINDING`. The evidence is the interface index's resolved-import flags, not an identifier scan: a qualified reference the checker accepted marks the import it resolved through, a binding that reused the first segment of a dotted path stays an ordinary value, and the alias inside a string literal or comment is not a reference. A cached body that was replayed rather than re-checked recovers its usage from the qualified names in its module's own source, so a warm run reports the same imports as a cold one. The warning is `W_*` and therefore rejecting under a configured `lint.warnings: "deny"` exactly like the other codes, and `import_policy` continues to evaluate every resolved direct import, used or not.
- [MUTATION-ENFORCE-1] Within a checked call, an input not listed in `mutates(...)` cannot have its reachable mutable objects written by that call or its transitive callees, and a function with no `mutation` effect cannot write caller-owned managed state. Origins propagate deeply through records, arrays, options, unions, collections, helper results, wrappers and shallow copies; definitely-fresh local storage stays writable; unknown is never fresh. A writable input graph that may overlap a read-only argument of a declared `mutates(...)` contract rejects with both argument sites unless proven disjoint, while two writable aliases are permitted; inferred writes of an unannotated callee are not a contract and carry no overlap obligation. Callee footprints substitute into actual arguments to a fixed point through recursion, unused generics, specializations and indirect callbacks; analysis-budget exhaustion widens conservatively with a located limitation. The guarantee is call-duration only and makes no total/trap-free/allocation-free/concurrency claim.
- [MUTATION-MARKER-1] An opt-in `--mutation-markers` flag adds a caller-side `&` marker for input mutation. With the flag on, every argument bound to a parameter position named in the callee's declared `mutates(...)` footprint must be written `&argument` (`shuffle(&xs)`); an argument on an undeclared position, a non-assignable argument, or a missing marker is a located `E_MUTATION_MARKER` whose message names the exact replacement. The rule applies to resolved direct calls and to calls through callable values with a `mutates(...)` binder. With the flag off, `&` stays a removed spelling and no existing program changes.
- [INCREMENTAL-SPEC-1] A generic specialization key mixes the template identity, canonical concrete arguments, the concrete provider type shape (fields, variants and layout flags), the target ABI and the compiler build identity; a provider-shape edit invalidates the key even when the template is unchanged.
- [INVALIDATION-EXECUTION-1] An invalidation report records actual query work: a stage a command did not run is reported `skipped`, never as reuse; lowering, emission and linking consume body and emitted-fragment inputs, so a body edit invalidates them; and a rejected check emits a best-effort explanation against the previous baseline without publishing a successful verdict.

- [CLI-2] Reports missing arguments and missing source files as usage or host failures.
- [EXIT-STATUS-1] The entry point's `int` result is the process exit status, the way a Python or Go program returns an exit code, truncated to the low 8 bits (POSIX `waitpid`: `status = value & 0xFF`), for `mylang run`, `run-project` and a native executable from `mylang build`. So an entry returning 7 exits 7 and one returning 256 exits 0. `--print-result` still writes the full value to standard output and is orthogonal to the status, so a program can print its result and exit with it at once. Unit and Result entries adapt first ([PYTHON-CORE-2]): a `unit` or `Ok(unit)` entry exits 0, an `Ok(n)` or `int` entry exits `n & 0xFF`, and an `Err(code)` entry exits `code & 0xFF`.

- [GENERIC-CONCRETE-1] Abstract generic checking resolves concrete copyable nominal and fixed-array schemas without conflating them with type parameters. Concrete record/array construction and projection obey declared field, element and index types; malformed uncalled templates reject. Concrete owned flow follows GENERIC-OWNED-1; individual runtime operations require their own abstract rules. Concrete result obligations follow GENERIC-RESULT-1.

- [GENERIC-UPDATE-1] Generic bodies may update concrete copyable records and replace fixed-array/table elements. Field uniqueness and field/element/index types are checked before instantiation; normal specialization preserves immutable snapshots, evaluation order and runtime bounds. These operations do not infer structural capabilities for symbolic parameters.

- [GENERIC-VARIANT-1] Abstract generic checking supports construction and exhaustive matching of concrete copyable enums/unions. Cases retain nominal identities and exact payload types; each arm scopes its payload independently, duplicate/missing cases reject, and a match terminates only when every arm terminates. Named enum-table construction requires every key exactly once. Result-bearing variants follow GENERIC-RESULT-1; runtime-owned value flow follows GENERIC-OWNED-1.

- [GENERIC-RESULT-1] Abstract checking of concrete result-bearing generic values enforces single transfer, explicit handling, scope/return obligations, and agreement across continuing branches, match arms, loops and short-circuit paths before instantiation. Nested payloads retain obligations and aggregate operations cannot erase siblings or replaced results. Propagation requires compatible concrete result errors and rejects live result bindings or previously evaluated result temporaries on its early-return path. An explicit `_ =` release evaluates its operand. Symbolic result type constructors remain pending.



- [GENERIC-CLEANUP-1] Concrete resource ownership passed through generic functions retains its provider lifecycle. Explicit partial extraction/drop and implicit scope cleanup release each live resource exactly once, including allocation failures and traps; forwarding does not complete or duplicate an external resource.


- [GENERIC-PROVIDER-1] Abstract generic provider operations enforce concrete or symbolic nominal result contracts, exact capability kinds and fixed byte-array inputs before instantiation. Resource I/O requires a mutable unconsumed owner after argument evaluation. Acquisition/completion preserve resource ownership and permission attenuation cannot create authority. Direct clock/random/environment/filesystem/network effects propagate through helper calls and enforce bounds even in uncalled or unreachable source paths.

- [GENERIC-PROVIDER-EXEC-1] Generic provider execution preserves ordinary callback values/counts, bounded output bytes, typed failures, retry ownership and cleanup under allocation failure. Short-circuit paths remain unevaluated at runtime while their possible effects remain statically checked.






- [DIAGNOSTIC-JSON-1] CLI --diagnostics=json selects diagnostic-v1 JSON Lines on stderr without changing command results or exit statuses. Source and VM diagnostics preserve stable codes, severity, original-file byte ranges and byte-based line/columns, related/origin/requirement notes, bounded frames and omitted-frame counts. Project-loader related sites retain their own module coordinates. Auxiliary CLI messages are separate message records. Successful check-session warning replay uses the selected format, and cache identity prevents cross-format replay. Default text remains available; invalid command-line syntax and emergency output failures may use text.


- [HOST-SOURCE-1] Contextual host fn declarations have no guest body and require an explicit effects(host, ...) contract. Only ordinary top-level, non-generic copied data signatures are supported; capabilities, managed collections and runtime-owned graphs reject. Main retains a guest body. Host and additional declared effects propagate through ordinary and abstract generic calls, including uncalled templates. Effect-free evaluation/invocation cannot execute these calls. Modules, formatting and disassembly preserve declarations; duplicate discovery excludes external implementations.


- [BOARD-TRIAL-1] The bounded board-validation experiment runs its guest as a native executable with a trusted geometry provider linked into it, compares deterministic reports and callback counts with an independent fixed oracle and standalone Zig implementation, and releases snapshot and callback graphs on allocation failure.

- [NOMINAL-BODY-1] Generic bodies retain nominal declaration identity and ordered symbolic arguments, check fields and payloads before calls, and preserve construction, assignment, exhaustive matches, named result propagation, partial ownership and cleanup effects. Substitution and late VM catalog materialization retain stable type IDs and reuse existing numeric array shapes. Phantom arguments retain identity without contributing stored-value contracts. Shape traversal uses an explicit stack and the generic checking work budget; argument-growing runtime specialization remains bounded by the nominal graph/name limits. Ordinary unconstrained type parameters still require structural constraints for member operations. Provider-specific symbolic shapes follow NOMINAL-PROVIDER-1; public generic schema tooling remains pending.

- [NOMINAL-PROVIDER-1] Generic resource/environment operations accept symbolic nominal result and payload records only when their exact named fields satisfy the ordinary provider contract for every permitted substitution. Declaration order does not affect meaning. Byte inputs and output arrays must have known u8 elements and numeric lengths; a general integer parameter is insufficient. Concrete and symbolic checking share named contract definitions. Resource identity, authority, mutable access, handling, cleanup and effect checks remain enforced before calls. VM specialization preserves bounded bytes, absent environment values, partial I/O, failed-completion ownership and cleanup under allocation failure or instruction traps.

- [GENERIC-CODEC-1] Generic domain codec metadata preserves exact value types, result obligations, transitive effects, declaration privacy and module relocation for tooling. The former `codec_encode`/`codec_decode` source entry points are removed; `wrap`/`unwrap` still require the exact declaring domain and private methods remain inaccessible outside it.

- [BOARD-ABSTRACTION-1] The board trial uses a shared Slot<T:copy> for optional IDs, regions, features and first violations, and one equality-constrained membership helper for component/net IDs. Typed snapshots preserve each instantiated slot's exact payload identity; a NetId payload cannot enter a component slot. Consolidation preserves the fixed board contract, oracle results, callback counts and repair fixture failure/restoration behavior.

### Disk application raw byte host

- [BYTE-IO-1] The raw byte host preserves arbitrary input, enforces bounds and publishes output only on successful guest exit. Its operations are a trusted native provider compiled into the guest's own executable, which buffers output where only the driver can publish it.

The `mylang-io --project DIRECTORY` host compiles `main.my` and its imports from
disk into bytecode. It supplies only `io::length() -> i64`,
`io::byte(index: i64) -> u8`, and `io::put(value: u8) -> i64`, each with host effects.
Input bytes are passed untouched, including invalid UTF-8 and NUL. The guest owns
parsing, validation, algorithms, and serialization. Input is bounded at 2 MiB;
output at 128 MiB; a put returns zero on success. Negative/out-of-range reads and
output exhaustion fail the host call. Output is published only after guest main
returns zero, never after traps or nonzero exits. The host supplies no external
filesystem, network, environment or process authority to the guest. Host calls/work
are bounded at 300 million each and guest execution at 2 billion steps; the coordinator
also enforces wall/CPU/memory limits. The executable is built outside application
sessions; editing guest files requires no Zig rebuild or language Guardian run.

- [STANDARD-MODULES-1] Reserved standard sources load identically through all project providers and participate in source budgets, dependency graphs and digests. They are ordinary Python-syntax guest modules over managed types and may import one another.

- [PLAIN-JSON-1] The strict document parser produces a checked i64 tape for a JSON text. It rejects duplicate decoded keys, invalid Unicode, integers outside i64, nonfinite numbers, trailing data and container depth over 64. Its byte budget is at most 1 MiB; scratch and output allocation remain bounded.
- [PLAIN-JSON-2] Ordinary JSON validation applies to every subtree, including unused fields: decoded duplicate keys, malformed UTF-8, out-of-range integers, nonfinite floats, trailing bytes and excessive nesting reject.
- [PLAIN-JSON-3] Failed document parsing releases partially allocated DOM, tape and text storage.
- [STANDARD-MODULES-2] Embedded standard source bytes count against the same per-file and total project source budgets as user modules.

## Guest application test tool

- [NATIVE-TEST-1] `mylang test` checks the project and discovers `test_`-prefixed declarations: every exported one, and an unexported one only when it already has the defaulting shape — no generic parameters, no value parameters, and a `bool` result — so a private helper named `test_` never aborts a run. A discovered test whose shape cannot default (value parameters without `arguments`, or a non-`bool` result without `expected`) is reported as one failed case rather than a host failure. It validates named typed JSON inputs and compares native results structurally. Filters and reasoned skips never turn an empty or all-skipped selection into success. Each execution uses a fresh bounded native process without implicit host grants.
- [NATIVE-TEST-2] Successful deterministic tests may reuse verified receipts keyed by semantic dependency closure, call signature, relevant layouts, case settings, execution limits, and tool/runtime identity. That identity follows QBE-4: the compiler's embedded build-time digest, and path, size and modification time for external tools, rather than rereading executables on every run. Whitespace and unrelated body edits preserve valid results; affected helper edits invalidate consumers. Corrupt receipts are misses; failed or externally effectful executions are not reused. `--force` executes selected unskipped tests.
- [NATIVE-TEST-3] Provider fixtures replace only existing dependency sources in private bounded snapshots, preserve the selected test signature and exported types, and never edit originals. A source change observed during one invocation and any compiler change invalidate results before publication, but an unrelated source edit no longer invalidates an unaffected receipt: acceptance is bound to the selected test/provider dependency closure, contract identity and provider identity, with the whole-snapshot source identity retained for during-invocation change detection and diagnostics. Native reports distinguish passed, cached, failed, and skipped cases; setup failures exit 2 and empty/all-skipped selections exit 3.
- [NATIVE-TEST-4] A directory argument selects every project root beneath it in sorted order — a `.my` file that declares a top-level `main`, plus standalone `*_test.my` files — treats library modules imported by a root as part of that project rather than programs of their own, skips generated trees, and runs one bounded child command per root across the machine's cores. Child reports merge into one case listing, one count summary and the most severe exit status, and children share the object cache and receipt directory so an unchanged program reuses its results instead of rebuilding. A filter carrying no `*`, `?` or `[` matches any substring of a qualified test name; one carrying them keeps shell-style wildcard semantics. A per-case configuration file is rejected for a directory run, because its keys name the tests of one project.
- [NATIVE-TEST-5] Before checking any production implementation body, native test preparation parses every reachable module and validates exported declarations and interfaces, then reads the case configuration and fully checks only the selected replacement provider graph. The declaration manifest carries canonical declaration-level type descriptors that normalize builtin aliases and expand transparent aliases while preserving nominal identities, and discovery and provider comparison consume those descriptors without checking unselected production bodies. Replacements are validated against every public contract they replace — names, defaults, canonical types and nominal identities, data shapes, generic requirements, declared effects, mutation footprints and return-origin bounds — using the directional subset relation, so a narrower implementation is accepted and a stronger one rejects. An unselected production body may contain a typed hole or body type error while its declarations remain valid; a production interface error, a malformed or unknown replacement, or a syntax error still rejects, and a full production build still rejects the unfinished body. Test receipts record the selected dependency-closure key plus the contract and provider identities, so changing a fake value or a relevant contract re-executes its case. Identical provider graphs share one declaration validation, checked project and prepared native library per invocation; distinct provider graphs stay isolated.
- [NATIVE-TEST-6] After a project validity check through the shared query cache, a warm unchanged deterministic native-test run looks up valid result receipts and executes zero tests without lowering, emitting or linking any code; only the declaration and validity checks run. Cached execution is admitted only with the closure-bound plan key, contract identity, provider identity and fixture/environment/budget identities, so a helper edit executes only its dependent tests and changed expectations, arguments, providers, environment, budgets or force mode invalidate exactly the affected receipts. A fully cached selection additionally requires durable checked facts (`native-test-graph-v3`) whose key covers compiler/tool stamps, mode, environment hash, source identity and canonical provider identity; a wrong or damaged graph is a miss. When facts or receipts miss, one checked compilation per selected provider graph produces the test facts and is retained: a later selective lowering request consumes that same checked result instead of re-checking the project in a second process, and any fallback recheck is reported as real checked-body work rather than hidden. Only the selected tests' reachable function closure is lowered, emitted and linked; callbacks, function values, codec boundaries and any indirect-call set widen conservatively rather than omitting required functions. Identical provider graphs share one prepared closure and library, while distinct graphs stay isolated.
- [PURE-SKIP-1] `mylang test --pure-skip` may replay a recorded pass-or-fail outcome for an unchanged test that is both effect-cacheable and signature-pure (no capability parameter and no declared `mutates(...)` footprint) without executing it and without depending on the positive-only receipt. The record is keyed by the same semantic dependency-closure key, contract identity and provider identity as the receipt, and additionally binds the expected value; a recorded failure replays as a failure with its message and never as a pass. A changed dependency, provider, contract or flag is a miss and re-runs, and `--force`, `--no-cache` and any non-pure test never take the path. Without the flag the default result is unchanged.

- [NATIVE-TEST-7] `mylang test` runs each case with the guest's stdout redirected off the runner's binary protocol channel: the child captures bounded output and returns it in the response, the parent appends it to a failure's text, a passing case discards it, and a benchmarked function's output goes to the diagnostic stream. `print` inside a guest test therefore never aborts a run with `InvalidNativeTestResponse`.

- [NATIVE-TEST-8] A failed typed expectation reports both sides of the comparison as `expected <value>, got <value>` — a Boolean test shows its actual and expected values — while a trap keeps its located code and any captured guest output.

- [NATIVE-TEST-9] A guest test entry need not declare `main`: a library module or a standalone `*_test.my` file is checked through a private projection that appends a stub entry point, and a matching `module` header when the file has none, while the `main` requirement for ordinary `run` is unchanged. A standalone `*_test.my` beneath a subdirectory resolves its imports and dotted module name from the enclosing project root — the nearest ancestor holding `mylang.json`, else the nearest ancestor holding a non-test `.my` source — so `tests/parser_test.my` is module `tests.parser_test` and `import sexpr.parser` reads from the project root. A child compiler's located source diagnostic is surfaced alone with exit status 1 rather than wrapped in the generic host-failure line.

- [NATIVE-TEST-10] A failed `assert` reports the message written after its condition: the per-function native metadata carries one message per program counter, `mylang test` renders it as `R_ASSERT: <message>` in the failure text beside the located code and any captured output, and `mylang run` shows the same message on its human diagnostic; an assertion with no message keeps the bare `R_ASSERT`, and a message containing JSON syntax leaves the versioned trap record valid.
- [AFFECTED-TEST-1] `mylang test --affected --against REF` derives its selection from the working-tree diff rather than from the standing tree: it checks the project, maps each declaration's merged source span back to its module file and original line range, intersects that range with the changed lines `git` reports for `REF`, and runs a discovered test only when a changed declaration is reachable from it over the resolved call graph. It is a selection and never a verdict: the selected count and every skipped test are printed, `--filter` still applies first, `lint --gate` and CI run the whole set, and an empty derivation exits 3 exactly as a filter matching nothing does. `--against` without `--affected` (and `--affected` without `--against`) is a usage error, and a `REF` `git` cannot resolve is a host failure (status 2) rather than an empty selection. A project that cannot be checked for any other reason runs the whole discovered set instead of silently skipping tests.
- [GUEST-TEST-GC-STRESS-1] `mylang test --gc-stress` runs every collected test's copied-value call with the runtime's stress collector, the same collector coverage `native_execute` gets from its own `--gc-stress` argument, and a directory run forwards the flag to every child so one invocation reports one collector condition. The flag adds no expected value of its own, is part of the execution identity a receipt binds, and without it the collector is not stressed and the default result is unchanged.


## Guest performance benchmarks

- [NATIVE-BENCH-1] `mylang test --bench PATTERN` discovers exported `bench_` functions beside `test_` functions and reuses the same cases file for typed arguments, expectations, provider substitutions and named input sizes, each size becoming its own stable benchmark ID `name[size]`. Boolean results default to true and other result types require an explicit expectation, exactly as correctness tests do. Benchmark filtering is independent of test filtering; correctness tests run first and must pass before any measurement, and `--bench-only` skips them for local iteration. Malformed settings, unknown case keys and missing expectations reject instead of silently skipping a benchmark.
- [NATIVE-BENCH-2] Each benchmark invokes the complete native copied-value call, including argument and result codec costs, and measures it inside the native subprocess with a monotonic clock after warmup and calibration to a target batch duration. Compilation, process startup, library loading and report serialization are excluded from the declared timing. The harness reports raw batch durations and iteration counts, median nanoseconds per operation, interquartile spread and sample count, validates the returned value outside every timed region, and keeps the workload observable. Every operation is a fresh copied-value call, so no guest state carries between operations. A trap, an incorrect result, a timeout or an invalid output fails the run and is listed in the candidate's failures instead of producing a measurement.
- [NATIVE-BENCH-3] Three distinct versioned artifacts exist: the approved `perf/baseline.json` with measurements, inventory and provenance; `perf/policy.json` with default and per-benchmark limits, the required suite, runner profile and noise budget; and a fresh run report or candidate. Malformed data, unknown versions, duplicate benchmark IDs, invalid numbers and nonpositive timing baselines reject. A baseline is never replaced while it is being checked, candidate writes are atomic, and a candidate clearly states whether every required test and benchmark completed so an incomplete report cannot become an approved baseline. Each measurement carries its benchmark ID, workload version, fixture identity, measurement-boundary version, optimization mode, sampling configuration and runner profile, with source revision, compiler, toolchain, OS, CPU and environment recorded as provenance.
- [NATIVE-BENCH-4] Comparison is lower-is-better. A relative regression is flagged only when `(C - B) / B` exceeds `allowed_growth_percent / 100` and `C - B` exceeds `minimum_meaningful_delta_ns`; an independent `max_ns_per_op` ceiling applies even when relative growth is small; equality with a limit passes and zero percent tolerance is valid. Only runs whose workload version, fixture identity, boundary version, optimization mode, runner profile and sampling configuration match are compared, and the code-under-test implementation hash is deliberately not part of that key. Unbaselined, removed, skipped, incompatible and missing results produce explicit incomplete-coverage or incompatible verdicts rather than a green gate. A noisy or near-limit result earns at most one predefined confirmation run whose samples are evaluated together; unresolved noise is inconclusive and never silently passes.
- [NATIVE-BENCH-5] The approved baseline stays fixed until a reviewed promotion replaces it. Promotion requires a complete, passing candidate and records the approver, reason, revision, runner profile and old and new measurements in retained history, so successive accepted regressions stay visible and a successful build never advances the baseline by itself. A local comparison writes no baseline, a candidate cannot raise its own limits to pass, and the baseline and policy formats serve a later compiler benchmark adapter through distinct benchmark IDs and timing boundaries.
- [NATIVE-BENCH-6] A directory benchmark run discovers and measures each program's benchmarks with a fan-out width of one, so timing batches never compete with each other, and a failing correctness test in any child blocks that program's measurements. Because a directory run has no single aggregate benchmark report, it rejects `--bench-output`, `--bench-baseline` and `--bench-policy`; each child's most severe exit status carries its own performance gate.

## Guest memory ceilings

- [MEMORY-CEILING-1] Every process that runs guest code runs under a byte ceiling. The soft ceiling is the managed heap's own budget: an allocation that would exceed it after a collection traps with `R_MEMORY_BUDGET`, "memory budget exhausted", and exit status 1, rather than growing. The ceiling travels in `MYLANG_MEMORY_LIMIT` as bytes with an optional `K`, `M` or `G` suffix, so no spawner needs a new argument ABI and a program started by hand under an exported variable is bounded the same way; malformed text refuses the run instead of leaving it unbounded, and zero removes the ceiling. `--max-memory=BYTES` on `run`, `build --run` and `test` outranks the variable, which outranks the built-in default: 512 MiB for one test child, 4 GiB for `run` and `build --run`. A resolved test ceiling is part of a receipt key, so changing it re-executes rather than reuses.
- [BUDGET-HINT-1] A native budget trap reports the flag that raises it instead of a generic failure: `R_STEP_LIMIT` answers "instruction budget exhausted; raise it with --max-steps=N" and `R_FRAME_LIMIT` answers "call-depth budget exhausted; raise it with --max-frames=N", with or without a located guest trace, in text and in the message field of `--diagnostics=json`. Every other runtime code keeps the text it had, and `R_MEMORY_BUDGET` still answers "memory budget exhausted".

- [RUNTIME-UNBOUNDED-1] `mylang run`, `mylang build --run` and a binary built by `mylang build` count instructions and call depth without a default ceiling: a program is stopped only by `--max-steps=N`, `--max-frames=N`, the byte ceiling, or `--timeout=SECONDS`. An embedded library run with zeroed `MylangRunOptions` is unbounded the same way. `mylang test` keeps its per-test guard of 1,000,000 instructions and 1,024 frames.

- [RUNTIME-TIMEOUT-1] `--timeout=SECONDS` on `mylang run`, `mylang build --run` and a built binary arms a monotonic wall-clock timer inside the guest; when it fires the process writes `R_TIMEOUT: wall-clock budget exhausted; raise it with --timeout=SECONDS` to standard error and exits 1. There is no default timeout, and a zero, empty or non-numeric value is a usage error.
- [MEMORY-CEILING-2] Behind the soft ceiling the runtime caps its own address space with `RLIMIT_AS` at the budget plus fixed headroom, before its first allocation, so a runtime defect cannot outgrow the budget. It never loosens a tighter ceiling already in force and installs none under a sanitizer, whose shadow mapping reserves more address space than any budget allows. The compiler bounds itself the same way at start-up, at 8 GiB unless `MYLANG_HOST_MEMORY_LIMIT` says otherwise, and the tools a native build spawns complete under the inherited ceiling. Every host that runs a guest in its own process — the byte runner, the board trial and the schematic renderer — installs that same ceiling before it runs anything, because there a runaway guest is a runaway host.
- [MEMORY-CEILING-3] A directory test run fans out over the cores the machine has, further limited by how many per-child ceilings its reported free memory holds, so a cold run on a loaded machine waits instead of oversubscribing. `--jobs N` outranks `MYLANG_JOBS`, which outranks that derived width; zero and non-numeric widths are rejected, the width never exceeds the programs there are to run, and it is never less than one.

See `docs/experiments/guest-tests.md` and `tests/native_test_cli.py`.

## Installed feature identity

- [FEATURE-REPORT-1] `mylang --features` reports `language-features-v1`, the compiler
identity, pinned Zig version and embedded feature/restriction manifest, without reading
its own executable. `compiler_sha256` is that identity: a build-time SHA-256 over the
compiler's source inputs, Zig version and optimize mode, embedded when the compiler is
built. The same identity appears in every receipt's `implementation`, so a receipt and a
feature report from one compiler always agree. The current reference is
`docs/current-language.md`; historical checkpoint prose does not supersede it. The
manifest records implementation coverage, not a test certificate.
- [FEATURE-REPORT-2] The manifest's `implemented` section is a JSON object keyed by feature
slug. Every entry carries `kind`, either `language` or `tooling`, a one-line `summary`, and a
`doc` pointer of the form `<page>.md#<heading-anchor>` naming the documentation section that
demonstrates the feature. A slug that stops describing a real form moves to `removed` with a
date and a note rather than disappearing.
- [DOCCOV-1] `mylang doc-coverage [<repo-root>]` resolves every implemented feature's `doc`
pointer against that checkout. A pointer without an anchor, a page that does not exist, a page
reached through a `..` component, a page under `docs/legacy/` whose examples the runner never
executes, and an anchor matching no heading are all reported failures.
A heading's anchor is its text lowercased with punctuation dropped, spaces turned into hyphens,
and hyphens and underscores kept; its section runs to the next heading of the same or higher
level, and headings inside fenced blocks are not headings. A `language` section must contain a
fence tagged `mylang` or `my` that the documentation runner executes — one tagged
`# doc: skip` or `# doc: not-mylang` does not count. A `tooling` section must contain a fence
tagged `bash`, `sh`, `console` or `text`, or an executable program fence.
- [DOCCOV-2] Every `export` of every `src/stdlib/*.my` module must be named as a whole word in
that module's `## <module>` section of `docs/standard-library.md`, every such section must
carry an executed example, and every exported definition must have a `#` comment line directly
above it in the module source.
- [DOCCOV-3] The command prints per-page feature counts, the standard-module and export totals,
and one line per failure, then a failure count. It exits 0 only when nothing failed, 1 when
anything is undocumented, and 2 for an unusable command line. A missing or malformed
`features.json`, an unreadable page and an unlistable `src/stdlib` are reported as failures
rather than host errors. `zig build test-doc-coverage` runs it, and the default `test` step
depends on it.
- [DOCTEST-1] `mylang doctest [<repo-root>] [--filter GLOB] [--report PATH] [--verbose]` walks
`README.md`, `SPEC.md` and every `*.md` under `docs/` recursively, except `docs/legacy/`,
extracts fenced `mylang`/`my` blocks, and applies the leading `# doc:` directives (`expect`,
`expect-error`, `check`, `project`, `file`, `skip`, `not-mylang`, `allow-read`, `allow-write`).
Blocks sharing a `# doc: project <name>` are materialised as one multi-file project under a
private temporary directory; every unit is then checked, run, check-project-ed or run-project-ed
by the running compiler with `--diagnostics=json` and the same `--print-result` and
`--restrict` capability-grant options the documentation gate used before. `expect` compares
trimmed standard output, `expect-error` compares `diagnostic-v1` codes, and the command reports
per-document tallies, mis-tagged prose fences and failures. `--report PATH` writes a
`doc-examples-v1` JSON report, and the command exits 0 only when nothing failed, nothing was
mis-tagged and at least one executable block was found.
- [DOCTEST-2] Units are independent, so `mylang doctest` executes them on a bounded pool of
workers that pull from one shared cursor, each unit keeping its own private directory, child
process and status. The width is `--jobs N`, then `MYLANG_JOBS`, then the machine's cores capped
by how many per-child memory ceilings its free memory holds — the rule and the ceiling
`mylang test <dir>` fans out under; a zero or non-numeric width is a usage error. Statuses are
collected and reported only after every unit has finished, so the per-document tallies, the
failure lines and the summary are byte-identical to a serial run whatever order the units
complete in; `--verbose` progress lines interleave but each is written whole under one lock. A
host failure in one worker leaves the units the other workers hold running.

- [DIAGNOSTIC-RECOVERY-1] Semantic checking recovers at ordinary and symbolic function boundaries after a source error, reports independent function faults in source order, and deduplicates repeated errors at the same source range and code. It stops within the failed function and skips whole-program verification when any body is incomplete; syntax, type-catalog, and namespace construction remain prerequisites. A failed check never publishes typed code or permits execution. Repeating a failed compilation check preserves diagnostics rather than appending duplicates.
- [DIAG-ORACLE-1] Type mismatches render the type the way source spells it, unknown fields and variants list the declared members, unknown functions suggest close candidate names, and arity errors report the expected and given argument counts.

## Managed arenas

- [ARENA-MANAGED-1] Python-style `with arena() as name:` and `with arena():` open a region over ordinary managed objects. Every managed allocation performed in the block's dynamic extent, including allocations inside called helpers, is tagged with that arena's nesting depth; arenas nest and the innermost one wins. Normal block exit releases every object allocated at that depth in bulk, dropping their outgoing edges before any header is freed, and reports the release separately from tracing reclamation in `memory.gc.statistics`.
- [ARENA-MANAGED-2] `name.escape(value)` deep-copies the part of the managed graph reachable from `value` that lives in the innermost arena into the enclosing region, preserving sharing and cycles inside the copy and sharing objects that already live in an older region. Escape carries the `managed_allocation` effect. The arena binding itself is opaque: it cannot be stored, passed, returned, or compared, only used as the receiver of `escape`, and `escape` must name the innermost active arena.
- [ARENA-MANAGED-3] Every managed object header records its arena depth and every store of a managed reference into a heap object is checked: list append, list slot writes, dictionary key/value writes, and values nested in record snapshots. Storing a reference of a younger arena into an older container traps with a located `R_ARENA_ESCAPE`, including stores performed inside helpers called from the block.
- [ARENA-MANAGED-4] Inside a `with arena()` block the checker rejects, with `E_ARENA_ESCAPE`, assigning a managed-bearing value to a binding declared before the block, returning a managed-bearing value, and direct stores into an outer-declared collection or record (`append`, indexed writes, dictionary writes, and field assignment). A managed-bearing type is any type whose values may hold a garbage-collected reference; scalars, enums, domains and records with only scalar fields are free to escape. `name.escape(value)` is the exception and may also be returned from the outermost arena scope of a function. Diagnostics name the escaping expression, the arena scope, and the outer binding, and render complete JSON provenance.
- [ARENA-MANAGED-5] Normal exit, `return`, `?` propagation, `break`/`continue` out of the block, and traps or host allocation failure unwinding through it all release the arena exactly once. Frame-owned values are released before the bulk free, and at an explicit block exit any binding declared before the block that still reaches arena storage traps with `R_ARENA_ESCAPE` as a defence in depth. An arena scope is always closed by the frame that opened it; a mismatched close is an internal-error rejection.
- [ARENA-MANAGED-6] Tracing collection continues to run at managed allocation safepoints inside an arena, including under `--gc-stress`; arena objects are traced normally and a swept arena object leaves its arena. Collection is suspended only for the duration of one `escape` copy, whose partly built clones are not yet rooted. Allocation inside an arena still contributes the `managed_allocation` effect, so `noalloc` rejects it; entering a scope itself contributes no effect.
- [ARENA-MANAGED-7] Arena scopes, bulk release, and escape copies unwind cleanly on every host allocation failure, leaving no live managed objects at execution teardown.
- [ARENA-MANAGED-8] Managed arena scopes lower on the QBE native backend. Every native managed object header records its arena depth, collection backing grows in its owner's region, the store barrier is emitted before each managed reference store whose element type can hold a collected reference, `escape` deep-copies into the enclosing region with collection suspended, `end_arena` scans the frame's outer bindings and clears the block's own before the bulk release, and every native frame restores its entry depth on return and while a trap, `?` propagation, `break`/`continue` or host allocation failure unwinds through it. An arena-free program emits neither barrier nor depth bookkeeping. Generic function bodies reject arena scopes with `E_GENERIC_BODY_UNSUPPORTED`.
- [ARENA-MANAGED-9] Locals are function-scoped, so a managed-bearing binding first assigned inside a `with arena()` block stays visible after the block, but it is confined to the released region: reading it once the arena is gone is a static `E_ARENA_ESCAPE` naming the binding, not a dangling read. Reassigning the name after the block re-homes it to the current region and clears the confinement; a scalar binding first assigned inside the arena carries nothing and is read freely. `end_arena` still clears the block's own managed slots before the bulk release, so no confined root survives into the next frame-root scan.

- [SURFACE-STMT-1] A statement ends at its newline, at the dedent that closes its suite, or at EOF; two statements written on one line are separated by `;`.
- [SURFACE-STMT-2] Postfix `?` propagates result errors and unwraps success with postfix precedence.
- [SURFACE-STMT-3] `None` and `()` both spell the unit type and unit value; a bare `return` before a newline or a dedent returns unit.
- [SURFACE-STMT-4] Calls and function parameters permit trailing commas; a delimiter continues an expression across newlines.
- [SURFACE-STMT-5] Parse-only declaration listing and module formatting preserve newline-terminated module, import, export, and type directives.
- [SURFACE-STMT-6] Project discovery recognizes newline-terminated directives and declarations while allowing multiline function signatures.

## Command-line authority

- [CAPABILITY-1] `Filesystem`, `Network`, `Clock`, `Entropy` and `Environment` are the canonical capability types. The removed `*_cap` spellings report `E_REMOVED_SPELLING` with the corresponding type; declared or imported types of the canonical name still win. Authority stays explicit: an entry point declares what it needs by parameter type, helpers receive grants as ordinary arguments, and no numeric cast or copy mints one.
- [CAPABILITY-2] `mylang run` and `run-project` grant every capability by default: filesystem reading and writing with no directory restriction, the clock, entropy and the whole process environment. `--restrict` switches the command to deny-by-default, and only then do `--allow-read=DIR` and `--allow-write=DIR` (each repeatable, up to eight directories), `--allow-clock`, `--allow-random`, `--allow-env` and `--allow-all` narrow anything; without `--restrict` they are accepted and narrow nothing. `--allow-random=SEED` pins the entropy seed in either mode, because it selects a stream rather than withholding one; an unseeded stream is seeded from the wall clock. `--allow-all` grants the clock, entropy, every environment name and read/write access to the working directory, and cannot be combined with another grant. A repeated flag, an empty-valued flag, and any of these options on a command that does not execute a program are usage errors.
- [CAPABILITY-3] Under `--restrict`, an entry point that names a capability the command line did not grant is rejected after checking and lowering but before the first guest instruction, with a message that says `--restrict` is active, names the flag that would grant the capability, and offers to drop `--restrict`; the status is 2. Without `--restrict` that refusal cannot happen. Grants for capabilities the entry point does not request provision providers that are never read.
- [CAPABILITY-4] The default filesystem grant is one direct root over the process working directory: a relative guest path resolves against it and an absolute path names itself, each operation applies the whole path at once and follows symlinks, and write authority is always present, so the default can never be narrower than a read grant. Under `--restrict`, directory grants are an ordered search path of scoped roots instead: a guest path must be relative with no empty, `.`, `..`, NUL or backslash component, it is tried against each granted root in order and the first success wins, traversal opens each component with symlink following disabled and final opens reject symlinks. Modes that change the tree — write, exclusive create, truncate, create directory and remove — consider only roots granted with `--allow-write`, which also grants reading that root, and a read-only grant rejects them before opening anything. Neither mode is a sandbox: the providers run inside the compiler process, the host filesystem tree is trusted, directory handles retain authority across renames, and directory scoping does not distinguish hard links to shared inodes.
- [CAPABILITY-5] The clock reports Unix-epoch nanoseconds from the host wall clock, with no monotonicity guarantee. Entropy is a reproducible pseudorandom stream, seeded by `--allow-random=SEED` when given and otherwise from the wall clock; it is not a cryptographic entropy source, and a program needing one must be embedded with its own provider. The environment exposes the host process environment, restricted to the `--allow-env=NAME,...` allowlist when one is given, reporting absent names as absent and denying names outside the list.

## Ordinary output

- [IO-1] `stream.print(values...)` writes each argument's Python rendering to the receiver stream's destination, separated by single spaces and followed by one newline. `int` and the fixed-width integers render in decimal, `bool` as `True`/`False`, `None` as `None`, `float` with a `.0` suffix when it has no fractional digits and `nan`/`inf`/`-inf` for the nonfinite values, `str` raw at the top level and `repr`-quoted inside a container, and `bytes` as a Python `b'...'` literal with `\n`, `\r`, `\t`, `\'`, `\\` and `\xNN` escapes. Lists render as `[a, b]`, insertion-ordered dictionaries as `{k: v}` and fixed arrays as `[a, b]`. Nesting deeper than 24 levels renders as `...`, so a cyclic managed graph still terminates. `stream.print()` writes only the newline.
- [IO-2] Records render as `Name(field=value, ...)` in declaration order, enum cases as `Name.case`, union cases as `Name.case(payload)` or `Name.case`, checked results as `Ok(value)`/`Err(value)` and optionals as `Some(value)`/`None`. Module qualification is stripped from the printed name. A record with a moved field prints `<moved>` for that field rather than reading it.
- [IO-3] `stream.print` accepts the keyword arguments `sep=` and `end=`, each an ordinary `str` expression that replaces the separator or the trailing newline. Positional arguments must precede both keywords, neither may be repeated, and any other keyword is rejected with `E_IO_ARGUMENT`. Printed values evaluate in source order, then `sep=`, then `end=`. Both keywords materialize the prelude `str` type on demand, so a program whose only text is a separator still checks, and a `stream.print` call without keywords needs no text schema at all.
- [IO-4] `stream.print` and `stream.write` contribute the `output` effect. `noio` withholds `filesystem`, `network` and `output` together, so a direct or transitive `stream.print` under `noio` is rejected with `E_EFFECT_BOUND` and a call witness; `effects(output)` permits it and `noalloc` does not constrain it. Bytecode validation independently recomputes the effect from the emitted instruction.
- [IO-5] `stream.print` is checked only on a receiver whose type is `Stream`; a bare `print`/`eprint` reports `E_OUTPUT_CAPABILITY` with the fix to add `out: Stream` and pass one from main, while a local binding or declared function named `print` remains an ordinary name. Capabilities, files, owned resources and callback values have no rendering and are rejected with `E_IO_ARGUMENT`. A host that supplies no output writer discards program output rather than failing, and a writer that refuses bytes traps with `R_OUTPUT`.
- [IO-6] The QBE native backend lowers `stream.print`. The compiler emits one C renderer per type a program actually prints, so every value shape renders byte-identically to `src/io_render.zig`, including `sep=`/`end=` raw text, the 24-level depth cap and the float spelling. A call buffers its whole line before any byte reaches the stream and flushes once; a refused write traps `R_OUTPUT`. Generic function bodies reject `stream.print` and the whole-path file builtins with `E_GENERIC_BODY_UNSUPPORTED` rather than reporting them as unknown functions.
- [IO-7] `with` is one statement form with two resource kinds. `with arena() as name:` opens a managed region; any other expression must produce an open file handle and must name its binding. `open(fs, path, mode)` takes a `Filesystem` capability, a relative `str` path and a literal mode — `"r"`, `"w"`, `"a"` with an optional `"b"` or `"t"` — and returns `Result[File, str]` for binary modes or `Result[TextFile, str]` for text modes. Directly as the head of a `with` statement the call yields the handle itself and a failure traps with a located `R_FILE`, the way Python's `open` raises; `with open(...)? as f:` propagates the result instead, and every other position yields the ordinary result. A binary handle's `read`, `readline` and `readlines` produce `bytes`; a text handle's produce `str`, decoded as UTF-8. `f.read()` reads to end of file, `f.read(n)` reads at most `n` bytes, `f.readline()` keeps its terminator, and `f.readlines()` returns the lines with their terminators kept.
- [IO-8] `f.write(data)` accepts the handle's own element type, writes every byte by looping over the provider's partial progress, and returns the count. `f.flush()` exists for familiarity and is a no-op because writes are unbuffered. Mode `"w"` creates the file or truncates an existing one, `"a"` appends at the current end, and `"r"` neither creates nor truncates. Whole-file reads and writes are capped at 64 MiB.
- [IO-9] `read_file`, `read_text`, `write_file`, `write_text`, `listdir`, `mkdir` and `remove` each take the capability first and return `Result[T, str]`, whose error text names the operation, the path and a readable reason. `exists(fs, path)` returns `bool` rather than a result. A helper opens, uses and closes its resource within the call, so a failure leaves no handle behind.
- [IO-10] A directory granted without write authority rejects every writing mode — `w`, `a`, create, truncate, `mkdir` and `remove` — before opening anything, and the returned error says the mode needs a write grant.
- [IO-11] A file `with` scope closes its handle exactly once at every exit: falling off the end, `return`, `?` propagation, `break`, `continue`, an explicit `f.close()`, and a trap or host allocation failure unwinding through it. A method on a closed or stale handle traps with `R_FILE`; so does any provider failure during a method, since `f.read()` yields bytes rather than a result. The trap message carries the same readable reason as the `Result` error text.
- [IO-12] File operations contribute the `filesystem` effect, so `noio` rejects them with `E_EFFECT_BOUND`. `with` on a value that is not an arena or an open file is rejected with `E_WITH_RESOURCE`, which tells a `Result` operand to propagate with `open(...)?` or match first. A non-literal mode, an unsupported mode and an unknown handle method are rejected with `E_FILE_ARGUMENT`. Generic function bodies reject file operations. The QBE native backend runs the whole file surface too, over a native scoped-directory provider with the same request grammar, `Result` error text and located `R_FILE` traps; an open handle is one owned resource word that the ordinary local drop closes at every scope exit. A native executable grants every capability by default and `--restrict` switches it to deny-by-default with the same `--allow-*` flags, which `mylang build --run` forwards after `--`.
- [REQUIRED-PROJECT-IMPORT-POLICY-1] A `mylang.json` discovered by walking up from the entry source file to the filesystem root makes its `import_policy` required for ordinary `check`, `check-project`, `build`, `run`, `run-project`, project variants and native test preparation, evaluated before any cached success and never selected from the shell working directory. Missing or malformed configuration is a host failure (status 2); a policy violation is status 3 and language or import-cycle errors stay status 1. Policy and configuration identity participates in verdict caches and receipts so a stricter policy invalidates an earlier pass, import-cycle checking cannot be disabled, and projects without a configuration keep their prior behavior.
- [TESTS-FOR-1] `mylang tests-for <entry.my> <qualified-name>` loads and checks the project, then prints the discovered tests that reach that declaration: a `direct` list of tests whose body calls it directly, and a `reached-by` list of every test that reaches it transitively. It is a selection aid, not a verdict: an unknown qualified name prints a message and exits 2, and a declaration no test reaches prints empty lists and exits 0.
- [REF-DIFF-1] The commit-time rules identify changed declarations from `git diff --unified=0 <reference>` run in the entry file's own repository: the changed working-tree line ranges come from the `+` side of each hunk header, and a declaration is changed when its source line range intersects one. A failed git invocation is a host failure, and the reference revision is never recompiled.
- [CHANGE-WITHOUT-TEST-1] Under `mylang lint --gate --against REF` only, every non-test function whose declaration changed since `REF` must be the direct callee of a test whose own body changed or was added in the same diff, be exempt under `test-coverage.exempt`, or carry a `change-without-test` waiver; otherwise it reports `L_CHANGE_WITHOUT_TEST` at error severity with a related note naming the tests that currently call it directly. A plain `lint --gate` without `--against`, and a baseline row under `.mylang/lint/`, never suppress it, because the rule judges a diff rather than the standing tree.
- [API-DIFF-1] `mylang api-diff <entry.my> --write=FILE` records an `api-diff-baseline-v1` snapshot of every declaration's stable identity and its interface and body fingerprints; `--against=FILE` classifies the current project against one snapshot as `additive` (a new identity), `compatible` (only the body fingerprint changed), `breaking` (the identity disappeared or its interface fingerprint changed) and `unchanged`, printing a one-line summary and the changed declarations by default or one `api-diff-v1` JSON object with `--json`. It is a report and never blocks: exactly one of `--write`/`--against` is required, and a malformed or unreadable baseline exits 2.
- [LINT-2] A `mylang.json` version 2 may carry a `lint` object: `profile` (`agent` default, `strict`, `safety`), `on_build` (`report` default, `block`), `warnings` (`report` default, `deny`), positive integer `min_chars` (the `undocumented-export` docstring floor, 12 by default), `block`/`ratchet`/`report` arrays of rule names, and a `rules` object whose per-rule settings carry positive integer `max`, `hard_max` and `recover_pct`, reasoned `exempt` and `allow` entries, and `modules` globs. Unknown or duplicate keys, malformed values, a non-object `lint`, and an exemption without a name or a non-empty reason are located configuration failures (status 2); `lint` requires `version: 2`, and a version 1 document keeps parsing without it. A configured `lint` object participates in verdict cache identity exactly as `import_policy` does.
- [LINT-1] `mylang lint <entry.my|dir>` loads the project through the shared frontend, runs every enabled rule over the checked program, prints each finding as an `L_*` diagnostic on stderr and one summary line on stdout. It exits 0 when the language is valid and no finding blocks, 1 for a source, type, effect or ownership error with no rule evaluated, 2 for a usage or configuration failure, and 3 when a blocking finding exists. Without `--gate` a `block` rule is reported at warning severity and never changes the exit unless the project sets `on_build: "block"`; `--gate` raises each block finding to error severity and refuses. `--json` (or `--diagnostics=json`) renders findings as `diagnostic-v1` JSON Lines on stderr, and `--profile=agent|strict|safety` overrides the configured profile for one run. A `# lint: allow <rule> reason="..."` comment on the line above a declaration waives that rule for it; a waiver without a reason is `L_WAIVER_REASON` and always blocks. The rules are `untested-export` (report under `agent`, block under `strict` and `safety`), `undocumented-export` (report under `agent`, block under `strict` and `safety`; a missing, too-short or name-restating docstring on an exported function, record, union or domain), `dead-private` (a private function with no call site), and the test-hygiene rules `test-no-assertion` (a test body whose every `return` is the literal `true` and which never asserts), `test-conditional` (a branch or match, or more than one loop, at a test body top level) and `test-empty` (an empty test body), all blocking under every profile. The advisory size and reach report-only rules — `function-length`, `parameters`, `nesting-depth`, `decision-points` and `dead-export` — are `.warning` under every profile and can never refuse; their thresholds come from `lint.rules.<name>.max` and default to 80 lines, 6 parameters, nesting 4, 10 decision points, and no caller anywhere in the project respectively.
- [LINT-3] `mylang lint --accept` writes the baseline and ratchet stores under `.mylang/lint/`, keyed on the checker's resolved declaration identity rather than message text. A baseline row `<module>|<qualified>` marks one existing finding as accepted debt: under `--gate` a blocking finding with a row is reported at warning severity and does not refuse, while a finding without a row refuses. A ratchet row `<qualified> <ceiling>` records a per-declaration ceiling for a threshold rule that may only shrink. A run without `--accept` never writes, prunes or lowers a store, baseline rows are sorted so the committed file is merge-friendly, and a store file containing merge conflict markers is refused rather than merged.
- [LINT-4] `integration-tests` (`L_TEST_CAPABILITY`) reports a discovered test whose declared parameters request `Filesystem`, `Network`, `Clock` or `Entropy` and whose module does not match the rule's `modules` globs (default `*_integration`, `integration.*`), because such a test is an integration test and belongs in an integration module. It reports under every profile and never blocks; a reasoned `exempt` entry or a matching module glob leaves the test alone.
- [LINT-5] The tests-reachability index built for `mylang tests-for` is shared: every `mylang lint` finding that names a declaration carries the discovered tests that reach it as a related note (a rule that set its own related note keeps it, and a declaration no test reaches gets none), and `mylang list-interfaces` prints a `tests(N)` column on each exported callable when bodies were checked, where `N` is the number of discovered tests that reach it directly or transitively.
- [LINT-6] The advisory section-9 report rules ship under every profile and can never block: `record-size` (`L_RECORD_SIZE`, a record or class over `rules.record-size.max`, default 7 fields), `file-length` (`L_FILE_LENGTH`, a module over `rules.file-length.max`, default 1000 non-blank non-comment lines), `bool-ops-per-condition` (`L_BOOL_OPS`, a single branch or loop condition combining more than `rules.bool-ops-per-condition.max` `and`/`or` operators, default 3), `naming` (`L_NAMING`, a function, parameter, local, record, union or domain that is not snake_case, PascalCase or off the vague-name list), `repeated-literal` (`L_REPEATED_LITERAL`, an integer literal other than `0`/`1` appearing at least three times in one module), `same-type-adjacent-params` (`L_SAME_TYPE_ADJACENT_PARAMS`, adjacent parameters sharing a non-capability type), `duplicate-body` (`L_DUPLICATE_BODY`, two or more checked functions with an identical normalized body, never blocking) and `output-in-library` (`L_OUTPUT_IN_LIBRARY`, a function whose inferred effects include `output` in a module outside `rules.output-in-library.modules`).

## Surface syntax

- [PYTHON-1] Sources use `def`/`record`/`class` heads, colon and space-indented blocks, `#` comments, implicit continuation inside delimiters, and source-preserving virtual block delimiters. A suite opens at the `:` that ends its line and closes at its dedent; `{` and `}` are only a dictionary literal, so a brace-bodied declaration is rejected. A suite's reported bytes end at the last token it wrote, so the blank lines and comments before the next declaration belong to neither, and a function's measured length and navigation excerpt cover only the function. Missing blocks, inconsistent dedents, and indentation tabs are diagnosed. Indentation is the only block syntax, so `fmt` returns the text a program already has.
- [PYTHON-2] Functions support ordinary mutable assignment, annotated bindings, `True`/`False`/`None`, `and`/`or`/`not`, `pass`, `elif`, omitted unit return annotations, `int` as i64, and square type parameters whose omitted requirement defaults to copy. `pass` spells an empty suite wherever one is written, including a record with no fields and a domain with no members. A `;` separates two statements written on one line, as it does in Python.
- [ATTR-1] A declaration may carry a fixed-vocabulary attribute on the line above it: @deprecated("reason"), @test, or @allow("rule", reason="…"). The parser rejects any other @name with E_UNKNOWN_ATTRIBUTE and a repeated attribute on one declaration with E_DUPLICATE_ATTRIBUTE. Attributes are part of the declaration header and the formatter round-trips them.
- [ATTR-2] @test makes a zero-parameter bool function a discovered test regardless of its name or export flag; mylang test, the native test schema and the W2 test rules agree on that set, and @test is reported in list-declarations and list-interfaces --contracts.
- [ATTR-3] A call to a @deprecated declaration from another module reports W_DEPRECATED naming the reason; the attribute participates in the declaration and project interface fingerprints, so removing a declaration deprecated in the baseline is an interface-compatible change once api-diff exists.
- [ATTR-4] @allow("rule", reason="…") on a declaration suppresses that lint rule for findings on the declaration and replaces the # lint: allow comment form; a reason is still mandatory (L_WAIVER_REASON). The comment form is still accepted alongside the attribute this round.
- [DOC-1] A triple- or single-quoted string literal that is the first statement of a module or of a function body is that declaration's docstring; it is inert, contributes no effect, and later standalone strings stay ordinary discarded expressions. list-interfaces shows its first line.
- [DOC-2] L_UNDOCUMENTED_EXPORT reports an exported function, record, union or domain with no docstring, one shorter than min_chars (12 by default, counted over non-whitespace characters), or one that merely restates the declaration name. It reports under agent and blocks under strict.
- [PY-RECORD-1] `record Name:` is the canonical declaration head for a nominal value record with annotated fields and named construction. `record` remains an ordinary identifier outside declaration position, so variables and parameters may still be named `record`; `class Name:` remains accepted as the compatibility spelling during the migration window.
- [PYTHON-3] Value records use `record` (or the `class` compatibility spelling) with annotated fields and named construction; square-bracket type applications and `match`/`case` preserve contextual variant names and underscore payload discards for semantic resolution. Every explicit type argument uses square brackets, including `todo[T]()`, `wrap[D](v)`, `codec_encode[D](v)` and the capability and resource operations.
- [PY-LAMBDA-1] `lambda name, ...: expression` is an expression-bodied spelling for the existing noncapturing function value. Its parameter and result types come from the expected `def(...) -> ... effects(...)` callback type, and invocation uses the same checked callback path as a named function value.
- [PY-LAMBDA-2] A lambda without an expected callback type is rejected. Its expression must match the expected result and exact effect ceiling; it may read its parameters and module constants but cannot capture a function local, whose diagnostic recommends a top-level function or explicit state parameter.

- [PY-VARIANT-1] `Type.case(value)` constructs an enum or tagged-union variant carrying its declared payload; `Type.case` without parentheses stays the payload-free construction and contextual `Ok`/`Err`/`Some`/`None` are unchanged. The payload evaluates once and `match`/`case` patterns keep the same spelling.
- [PY-GENERIC-1] `f[T](x)` applies explicit type arguments to a generic function, constant lengths included (`first[i64, 2](values)`), and a member call takes them the same way: `D.hidden[U](x)` on a domain method, `m.D.make[U](x)` on an imported one, and `m.make[i64, 2](v)` on an imported free function. An argument may name any type the lexer spells as a keyword, capabilities included: `hold[clock_cap]()`. A square-bracket application in call position names a function when the base is a declared function and a generic record otherwise, so `Box[T](field=v)` construction is unchanged and the nominal type catalog never resolves a function application as a type.
- [PY-GENERIC-2] Explicit call type arguments reach the same instance as inference, and the wrong number of arguments or an undeclared base name is rejected.
- [PY-FLOAT-1] `sqrt`, `floor`, `ceil`, `trunc` and `abs` are prelude operations on `float`, so guest code needs no `u64` bit pattern. Each takes one float and answers a float; a non-float argument is rejected, and a local binding or declared function of the same name shadows the operation.
- [PY-WILDCARD-1] `case _` in a `match` statement covers every variant no earlier arm named, discarding the payload of each one it covers.
- [PY-WILDCARD-2] A wildcard arm must be the last arm, must cover at least one variant, and is rejected when it would drop a result-bearing payload; that variant needs its own arm.
- [PY-SUBSCRIPT-1] A subscript index may begin with a parenthesis: `values[(n - 1) % 3]` is an index, because a square-bracket type application never contains a parenthesized group.
- [PY-RESERVED-1] `len` and `replace` are intrinsics only at the head of a call. Both name ordinary declarations, record fields, keyword arguments, members, exports and imported module members, so `strings.replace(...)`, `pool.len(p)`, `text.replace(old, new)` and a field named `len` are all spellable.
- [PY-LOOP-1] A `while True` loop with no `break` targeting it never falls through, so a function whose body ends in one needs no unreachable trailing return.
- [PY-PRELUDE-1] The `bytes` and `float` prelude types are registered wherever their names are written in source, including a variant payload, a record field and a bare annotation, rather than only where a literal or conversion appears.
- [PRELUDE-FOLD-1] `sum(xs)` adds every element of a `list[int]` or `list[float]` in order, starting from zero of the element type; an empty list sums to zero and any other element type is rejected.
- [PRELUDE-FOLD-2] `any(xs)` and `all(xs)` fold a `list[bool]` with `or` and `and`, stopping as soon as `any` sees `True` or `all` sees `False`; an empty list answers `False` and `True` respectively.

- [PRELUDE-SORT-KEY-1] `sorted(xs, key=callback)` stably orders a copied list by the integer returned from a noncapturing `def(T) -> int effects()` callback. The input remains unchanged, equal keys retain input order, the list is positional, and `key` is the only accepted named argument.

- [PRELUDE-ITERATION-1] `reversed(xs)` answers a new list of a list or string `xs` from last to first and is also a `for` source; `zip(a, b)` is a `for` source that walks two lists in step and stops at the shorter one; `list(...)` copies a list and materialises `list(range(end))` or `list(range(start, end))`.
- [PRELUDE-SHADOW-1] Every prelude builtin answers only when no local binding, declared function or module top-level name claims it, the same shadowing rule the other prelude operations follow.

- [PY-COMPREHENSION-1] `[value for name in iterable if condition]` builds a fresh list through one checked loop over a list, string, byte string or dictionary, under the same fixed iteration bound and mutation check as `for`. The filter runs before the value, the binding lives only inside the comprehension, and the source collection is unchanged.
- [PY-COMPREHENSION-2] A comprehension takes exactly one generator and at most one filter. A binding that shadows an active name, a non-Boolean filter, a source that is not a managed collection or an integer range, and a produced value that is not a copyable storable list element are all rejected. Generator expressions and multiple generators are not provided.
- [PY-COMPREHENSION-3] A comprehension accepts `range(...)` as its source exactly as a `for` loop does: `range(end)` and `range(start, end)` iterate a half-open ascending integer range whose bounds share one integer type, the binding takes each integer value, and the produced list has `int` elements when the body is the binding itself. - [PY-FSTRING-1] `f"..."` interpolates `{expression}` holes and concatenates the pieces into one `str`. A hole takes any value `print` can render — lists, dictionaries, records, variants, results, options and byte strings as well as scalars — and renders it through the same renderer, so one value has one spelling wherever it is written. A hole holds one ordinary expression, including calls, operators, indexing and a nested format string, and is checked in its own source position. `f` before a quote is the prefix; anywhere else it is an ordinary identifier.
- [PY-FSTRING-2] `{{` and `}}` stand for single braces, ordinary string escapes apply to the literal pieces, and an empty format string is empty text. An empty hole, an unmatched or unterminated brace, more than one expression in a hole, a format specification after `:`, and a value with no rendering — a capability, an open file or a callback — are all rejected. Rendering releases its partial buffer on allocation failure and reports it as `OutOfMemory`, the way every other allocating writer in the compiler does.
- [PY-SCOPE-1] Locals are function-scoped, like Python: an assignment to a name anywhere in a function body refers to one binding that is in scope from its first assignment to the end of the body, and a nested block reassigns the same binding rather than introducing a new one. The binding's type is fixed at its first assignment and later assignments stay assignment-compatible. A `for` loop variable and a `match` payload binding remain scoped to their own block, and a move-only resource stays confined to the block that must discharge its cleanup.
- [PY-SCOPE-2] Reading a function-scoped local that no control-flow path reaching the read has assigned is rejected with `E_UNBOUND` naming where the binding is first assigned; a name never assigned before the read is still `E_UNKNOWN_NAME`. An assignment in every continuing branch of an `if`/`elif`/`else` binds the name afterwards, and an assignment in only some branches does not. Every `while`, ordinary `for`, `range`, `reversed` and `zip` loop may execute zero times, so assignments made only in the loop body do not bind the name after the loop; a name read after the loop must have been predeclared before it.
- [PY-SCOPE-3] Every `match` arm starts from the same pre-match definite-assignment state. A local is definitely assigned after the match only when every continuing arm assigned it; terminating arms contribute no continuation. A wildcard body counts as the continuation path for every variant it covers. Payload bindings remain scoped to their arm, while an ordinary local introduced in an arm remains function-scoped and must be assigned on every continuing path before it can be read after the match.
- [PY-STR-1] `str` values answer `strip`, `lstrip`, `rstrip`, `upper`, `lower` and `zfill(width)` with a fresh string, leaving the receiver and every alias unchanged. Case mapping covers ASCII letters and leaves every other scalar alone; `zfill` keeps a leading sign in front of the padding.
- [PY-STR-2] `replace(old, new)`, `find(sub)` (-1 when absent), `count(sub)`, `startswith`, `endswith`, `isdigit`, `isalpha` and `isspace` follow Python's answers, including `False` for every classification of empty text. An empty needle traps `R_EMPTY_SEPARATOR`, and these methods are rejected on lists and dictionaries.
- [PY-STR-3] `splitlines()` splits on `\n`, `\r` and `\r\n` without keeping the terminators and yields no line for empty text. `int(text)` returns `Option[int]` and `float(text)` returns `Option[float]`, answering `None` rather than raising when the whole string is not exactly one number.
- [PY-STR-4] Every `str` method, scalar-value iteration and both number intrinsics lower to the QBE native backend over the immutable native text runtime, so no `str` operation reports `E_QBE_UNSUPPORTED`. A native `find`, `count` or `replace` with an empty needle raises `R_EMPTY_SEPARATOR`, and every method answers the value its documented semantics require.
- [PY-NUM-1] `int(text)` and `float(text)` accept one pinned base-10 grammar: optional surrounding ASCII whitespace, an optional `+` or `-` sign, then decimal ASCII digits separated by single `_` characters that must sit between two digits. `float` additionally accepts a `.` fraction, an `e`/`E` exponent with its own optional sign and digit run, and the case-insensitive spellings `inf`, `infinity` and `nan`. An alternate base such as `0x10`, a non-ASCII digit, an interior space, a trailing character and empty text are all `None`, and one shared vector table drives the checker and the native runtime so they cannot drift.
- [PY-NUM-3] A native program that parses numbers links the shared text runtime unit that holds the grammar, and `int(text)`/`float(text)` lower to an `Option` whose `Some` payload the runtime publishes and whose `None` carries no payload. A program that only measures or slices text links no such unit.
- [PY-NUM-2] `int(text)` answers `None` for a value the signed 64-bit range cannot hold rather than wrapping. `float(text)` is correctly rounded: a value beyond binary64 answers an infinity and one below it a signed zero, an absurd exponent saturates instead of wrapping, and digits past the rounding horizon are folded into a sticky digit that keeps the rounding the full text would have produced.
- [PY-ASSERT-1] `assert condition` checks a Boolean expression under any effect bound, in ordinary and generic function bodies, and traps `R_ASSERT` when it is false. The trap's source span is the checked expression and its default message is that expression's source text.
- [PY-ASSERT-2] `assert condition, "message"` reports the string literal instead of the expression text. Native lowering raises the same `R_ASSERT` code without the message, matching every other native trap.
- [PY-ASSERT-3] The message after assert may be any str expression, including an f-string; it is evaluated only when the condition is false and rendered to standard error immediately before the `R_ASSERT` trap, so a passing assertion pays nothing and a failed one names the values it saw. Because that expression may allocate, its effects count against the enclosing function's declared ceiling: a literal message stays free of effects, and an allocating message under `noalloc` or `effects()` is rejected.
- [PY-DIV-1] `divtrunc(a, b)` and `remtrunc(a, b)` are prelude helpers for integer division and remainder that round toward zero, the rounding `//` and `%` deliberately do not provide. They take two operands of one integer type, trap on a zero divisor and on the signed minimum divided by -1, and a local binding or declared function of the same name shadows them.
- [PY-CONVERSION-1] A `conversion` function body constructs its destination record as `T(a=v)`, under complete source-field accounting.
- [PY-VARIANT-3] A generic variant names only its template, because `Slot[T].some(v)` cannot be told apart from an index followed by a call. `Slot.some(v)` and the pattern `case Slot.some(v)` take their type arguments from the expected type — a binding annotation, parameter, field or result — in ordinary and generic function bodies alike, and report `E_GENERIC_INFERENCE` when no context supplies them. A project resolves the template through its own module names, so a declared or imported `m.Slot.some(v)` infers its arguments the same way.
- [PY-ARRAY-1] A list literal whose expected type is a fixed array `[N]T` — from an annotation, a parameter, a record field or a return type — constructs that array rather than a managed list, and a list literal in every other context still builds a managed list.
- [PY-ARRAY-2] Fixed-array literals check their length statically against the expected array, reporting `E_ARRAY_LENGTH`, and each element against the declared element type.
- [PY-TABLE-1] A dict literal whose expected type is an enum-indexed table `[Kind]T` constructs that table, its keys spelled `Kind.case` and its values arranged in enum layout order independently of source order.
- [PY-TABLE-2] Table literals require exactly one entry per case of their own key enum; missing cases, duplicates, non-case keys and cases of a different enum are rejected.
- [PY-VARIANT-2] Variant construction resolves through the declared type identity, so a local binding shadowing the type name keeps ordinary member resolution and a name that is not a declared case stays an ordinary call. Supplying no payload, more than one payload, a payload to an empty case, or a payload of the wrong type is rejected.
- [PY-VARIANT-4] A union case may declare named fields as `case(f1: T1, f2: T2 = default)`, with the same default-literal and required-after-defaulted rules as record fields. `Type.case(v1, v2)`, `Type.case(f1=v1)`, and positional-then-named mixing construct it, omitting a defaulted field fills its literal; a `case: T` payload and a payload-free `case` keep their existing spelling and meaning. `case Type.case(p1, p2)` binds one name per named field (`_` discards that field), a single-payload case still takes one binding, and a payload-free case takes none. Arity, unknown-field, duplicate-field, missing-required-field, pattern-arity and dropped-result diagnostics are located. Exhaustiveness, wildcard arms, result obligations, equality, layout and native lowering behave exactly as for a single payload.

- [PY-COLLECTIONS-4] Contextual nested literals preserve list types across fields and nested indexes.
- [PY-COLLECTIONS-5] Field assignment reconstructs mutable local records or list-slot records with receiver/index operands evaluated once, retaining value semantics for previous copies.
- [PY-COLLECTIONS-6] Generic list literals, iteration, slicing and writes preserve symbolic element types and allocation effects.

- [PY-COLLECTIONS-9] Generic record field updates preserve managed alias copying and concrete value semantics.

- [PY-COLLECTIONS-16] `values.index(value)` returns the first equal element's index or traps with `R_LIST_VALUE`; `values.copy()` returns a fresh shallow list holding the same elements in the same order so later mutation of either list is not observed by the other.

- [PY-COLLECTIONS-17] Dictionary `pop(key)` removes the matching entry and returns its value, `pop(key, default)` returns the default when absent, and `pop(key)` traps with `R_MISSING_KEY` when absent. `update(other)` writes every source entry into the receiver, replacing existing values while preserving their insertion position and appending new keys at the end; `setdefault(key, default)` returns the existing value or stores and returns the default. Insertion order remains the iteration order.

- [PY-COLLECTIONS-20] Reading an absent list value (`index` or `remove`) traps with `R_LIST_VALUE`, popping an empty list traps with `R_LIST_BOUNDS`, and popping an absent dictionary key without a default traps with `R_MISSING_KEY`; no absent value is silently replaced by a sentinel.

- [PY-AUGASSIGN-1] `+=`, `-=`, `*=`, `/=`, `//=` and `%=` assign the operator's own result back to an existing binding, so `float` bindings take the float operators, `str` bindings concatenate, and integer bindings take the integer operators. `/=` on a non-float binding is rejected with `E_TYPE` because its result is a float, and a non-integer, non-float, non-`str` target is rejected with `E_TYPE` as before.

The element type of `str` values concatenates and integer or `float` elements take their own operators.

- [REMOVED-SPELLING-1] Removed operation, type, capability, codec, raw-float and punctuation spellings report a located `E_REMOVED_SPELLING` diagnostic naming the canonical replacement, or state that dead punctuation has no replacement.
