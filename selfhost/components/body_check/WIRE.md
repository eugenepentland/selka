# Body-check batches through B6

B1 through B6 transfer body checking for every admitted ordinary function to a qualified Selka process. Native catalog construction, entry checks/adaptation, effects/origin/mutation passes, domain codecs and final warnings remain explicit host stages. Unsupported syntax produces a located profile refusal; selected modes never fall back to native body checking. Reference remains the default.

## Framing

The 64-byte outer frame is `SLKBCK01`, little-endian u32 protocol/schema `1/6`, direction `0` request or `1` reply, payload byte length at offset20, nonce8 at24 and request payload SHA256 at32. A reply echoes bytes24..64 exactly. Both complete frames are at most64MiB. Payloads are named postorder logical tables under `SLKBKI01`/`SLKBKR01`, using the existing parser value kinds0null,1signedi64,2bool,3bytes,4enum-tag,5namedrecord,6list,7taggedunion. Payload header contains value count and final root ID. References must point backward; duplicate/unknown fields, malformed tags, trailing bytes and correlation mismatches are host protocol failures.

## Request

`Input{context,program,modules,catalog}` has raw full AST `program` with the existing parser schema. Context is `{path,source,trusted_intrinsics,entry_required}`. Module is `{context,offset,imports,symbols,import_used}`. Its context/import/symbol fields use declaration DTOs unchanged; offset maps original bytes into merged source. Initial import flags are copied before any native shadow oracle mutates project state. The producer enumerates raw functions; the host supplies no body worklist. The retained native common phase supplies only `Catalog{string:?Sequence,bytes:?Sequence,base_count,lists:Sequence[],list_available,records:typed.Record[],templates:Templates}`, where `Sequence{id,element}` carries authenticated prelude identity and representation. Missing entries are unavailable, never inferred. String IDs use u32 elements; bytes IDs use u8. IDs are distinct in `[19,65555)`. Catalog defaults to empty for scalar-only test inputs. base_count is the complete retained record count, at most65536. Existing supported canonical list descriptors retain sparse native IDs in ascending order; unsupported element closures are omitted so raw unsupported syntax can reach a located profile refusal. List-only dependency chains may reference either ID order but must be acyclic and at most256 logical type nodes inclusive the terminal leaf. B4 separately admits ordinary record/list recursion as described below. list_available authenticates the native builtin List template. No native body decisions or inferred list worklist are transported.

## Reply

Outcome tags are `success`, `failure` and `profile`.

Success is `Output{batch,import_used,diagnostics,recipes:CatalogRecipe[]}`. Batch is `{nodes,statements,functions,ranges}`, preserving all `typed.Node`, `typed.Statement` and `typed.Function` logical fields and stable append order. Ranges contain `{nodes:{start,end},statements:{start,end}}` per raw function, in declaration order. They form exact contiguous partitions and assign even unreachable intermediate rows to one lexical local table. Calls reference global function IDs; local IDs belong only to their owning function. Type IDs use builtins i64=0, bool=1 and Unit=15, internal octets u8=5/codepoints u32=7, and the request's managed prelude IDs. Scalar integer literals use signedi64 wire values widened to native i128; B1 cannot encode wider integers.

The retained native catalog and entry phases may observe additional import uses
after the raw request snapshot. Before adopting or comparing successful bodies,
the host copies the producer flags and merges those common-phase observations.
Shadow captures this common state before native body checking, so missing
producer body observations still cause a mismatch. Neither the reply nor its
authenticated input snapshot is mutated.

Source failure is the complete ordered diagnostic array. Profile is `{code:"P_BODY_PROFILE",span,message}` and maps to host `ComponentProfile`. Diagnostic elements use the existing six-field SyntaxDiagnostic schema, including related/origin/requirement notes and structured fixes. Runtime traces or checker obligation pointers are rejected during oracle projection, never silently dropped.

## Bounds and validation

Sources:1MiB per original module,8MiB aggregate originals,4096modules,16KiB top-level path; merged source permits4096delimiter bytes beyond8MiB. AST and typed node/statement tables:262144each; functions and aggregate locals:65536. Logical transport:2097152values,4194304edges, depth256 and512MiB decoded allocation budget. These independent ceilings may reject a graph before its table cap. Graph validation uses at most4194304scheduled work entries and rejects cycles, cross-function node/statement/local references, incompatible scalar payload types, invalid call permutations, missing functions, bad declaration association, invalid parameter metadata, malformed range partitions and out-of-source spans. Failure diagnostics require at least one error; success diagnostics contain no errors. Initial true import flags cannot be cleared.

Validation is structural, not a second body/type checker. Semantic completeness comes from the authenticated producer and qualification against the native oracle. Shadow compares the entire canonical typed batch, all metadata/ranges, ordered diagnostics and import flags. Selected modes disable body semantic/specialization reuse. Aggregate frontend identity must be revalidated before either successful program or diagnostic publication. Adopted batch and diagnostics own caller-arena storage independently of the captured reply.

B2 adds copyable str/bytes annotations, literals, length/index, concatenation, comparison, mutable local reassignment, `+=` and marked mutable parameters while retaining complete typed functions, lexical usage and evaluation metadata. Batch fields are unchanged. Text literals are arrays of Unicode scalar-value u32 integer nodes (surrogates rejected); byte literals use u8 nodes bounded 0..255. Indexing str returns str; indexing bytes returns an internal u8 node converted to int. Managed indices retain `from_end=false` and use an int operand. Every managed identity must match the request catalog. Arbitrary nominal types and resource ownership remain outside this profile. Older schemas fail closed; reference remains the default.


B3 makes Selka responsible for new canonical list choices. Each recipe is `{id,element,span}`; IDs are exactly `19 + base_count + recipe ordinal`. Element keys are unique across initial descriptors and the delta; elements must be admitted scalar/text/bytes, an existing supported list, or an earlier recipe. Forward/self references, cycles, unsupported elements, duplicate recipes and noncanonical gaps are rejected. A recipe site must be an original AST node or statement span. The combined catalog remains bounded to65536 records and256 logical type levels. Lookup uses canonical ID binary search; validation uses bounded hash tables and memoized depth traversal.

The host materializes only these validated recipes in their declared order with the retained native List constructor and verifies every resulting ID, element and builtin schema. Shadow leaves the native oracle catalog untouched, observes its ordered added list identities and original semantic intern sites, compares the complete typed outcome, then materializes the producer recipes into an independent common catalog and compares complete canonical record schemas. Schema generation is retained native representation work; list selection and every admitted body decision belong to Selka.

B3 typed graphs admit list arrays or rooted acquire-buffer/append construction, list length/capacity with internal u64 then signed casts, and the exact closed operations read/write/append/contains/iteration_check/extend/insert/pop/pop_at/remove/index_of/reverse/sort/copy/clear. Operation owners belong to the current function; arguments and results must match the list element identity and operation arity. Unkeyed sort has no arguments, returns Unit, and requires int, str or bytes elements; keyed/callback forms are refused. Typed list addition retains the identical list operand/result type for native augmented writes; equality/inequality return bool. Source-level operator acceptance remains producer-owned. Loop iteration guards take signed limits. Internal u64 integer payloads remain bounded to signedi64 transport range; no wider numeric wire representation is implied. All function/table/range ownership and source-bound validation continues to apply.


B4 appends `records` as the sixth Catalog field, after `list_available`. These are the complete exact retained common schemas in dense ID order: `records.len == base_count` in the initial request, and record ID equals19+index. No native per-use type answers or nominal lookup table are supplied. Nongeneric user record declaration spans join directly to the raw AST and existing module symbols; the producer owns qualified name/privacy/alias/default decisions. Ordered fields retain their declaration spans, types, raw default AST IDs, box flags and full contracts. Projection snapshots top-level record values; nested schema slices are immutable retained data. Before recipe materialization, the host compares every retained canonical schema against the captured input.

The internal expanded view increases `base_count` for new lists while retaining the original `records` prefix. A bounded reverse-edge fixed point classifies ordinary copyable/storable value record and list closures, including finite record/list recursion. Unsupported member kinds propagate to every dependent record/list. By-value ordinary record cycles are rejected independently; list backing storage cuts layout edges. At most65536 total retained fields and131072 policy dependency edges are admitted. Every initial list descriptor must match its retained schema; delta descriptors have no retained row until independent materialization. New list recipes may use admitted retained ordinary record identities.

Typed `record` construction requires one unique initializer for every declared field with exact field value types; source/default evaluation order is preserved rather than sorted. `field` requires an admitted base, in-range field index and exact result type. `update` requires identical base/result identity and unique in-range fields with exact value types. Calls, locals, list element operations, ranges and copy/usage metadata retain all earlier checks. Shadow compares the entire typed batch and independently materialized final schemas.

All raw `@requires`, `@ensures` and `@invariant` attributes are preflighted globally, including unused/imported declarations. Native body checking otherwise inserts function-entry assertions, return postconditions and old-value captures, or synthesizes invariant validator functions; selected success cannot omit that work. Under schema 4, success also refuses generic/managed records, domains, variants/resources, boxed or unsupported record closures; these remain located producer profile refusals, with no native body fallback. Old schema3 replies fail closed. No seed profile or default routing change is implied.

## Schema 5: closed variants and checked failures

The outer frame remains `SLKBCK01`, protocol 1, with schema 6. Inner named-value graph magics remain `SLKBKI01` and `SLKBKR01`. Old schema 4 replies fail closed. Catalog's seventh field is `templates: {result: ?TemplateBasis, option: ?TemplateBasis}`; `TemplateBasis` fields are `id: usize, declaration: Span`. These are exact retained native builtin declaration identities, after name/kind/arity checks, not per-use type answers. A zero declaration span denotes synthesized canonical cases (`Result`: ok, err; `Option`: none, some). A nonempty span joins the original `std_result` raw declaration, preserving its parameter and case order. Unsupported nonparameter payload expressions remain profile refusals.

Output's fourth field is now `recipes`, replacing `lists`. Its tagged values, in global first-demand append order, are `list {id, element, span}`, `result {id, success, failure, span}`, and `option {id, element, span}`. IDs are contiguous from `19 + initial.base_count`, and arguments refer only to retained or earlier recipe identities. Duplicate canonical kind/argument tuples, unknown template authority and forward dependencies fail closed. Intern sites must be exact raw node/statement spans, function names or signature annotation spans, or catalogued suffix/application spans, not arbitrary in-source ranges. Signature Result interning uses the raw function name; call Result interning uses the callee's declaration name.

A temporary structural schema view derives case payload identities and ordered tags from these recipes and the retained template basis. It is not the final adopted schema: materialization revalidates the complete retained prefix, invokes only the producer-selected canonical constructors, checks each appended ID/recipe/site, and shadow compares all resulting canonical schemas against an untouched native oracle.

Ordinary unboxed enum/union and record/list/union closures use bounded dependency policy; finite list-backed recursion remains admitted. By-value cycles remain invalid. Pending Result-bearing elements cannot enter lists. Typed variant construction requires exact payload presence/type and in-range tags. Matches require one unique arm for every case and correctly typed payload locals. Propagation requires a compatible enclosing Result or Option and preserves its exact function return identity. Result transfer metadata is source-bounded and permitted only on Result-bearing types. All earlier function ownership, graph/range, source, codec and frame bounds remain in force. Raw function/invariant contracts, generic user functions/nominals, resources and boxed recursive layouts remain explicit profile refusals with no native body fallback.

A raw fielded standard Option basis requiring additional synthesized payload records remains an explicit profile refusal in schema 6. Direct-parameter reordered Result is target source syntax; the direct-parameter reordered Option native regression uses the migration parser solely to exercise raw transport authority. It does not claim that legacy Option declaration syntax is accepted by the target parser.


Schema 6 adds grouped `Templates.byte_buffer: BufferBasis{available:bool,identity:?Sequence}` and the global ordered recipe `.byte_buffer{id,span}`. Availability is exact existing builtin buffer/arity-zero authority or absence from both native declaration and raw alias indexes; identity authenticates the retained canonical managed byte/u8 schema. First-demand recipes preserve IDs and intern sites, use no body answer tables, and are independently materialized/full-schema compared. Closed buffer operations are length/read/slice, string text_tail and mutable buffer_reserve/buffer_append_byte/buffer_append_range, with exact result/operand/local types. Casts admit int-list to bytes/buffer and buffer to immutable bytes snapshot. Indexed byte_buffer writing remains the native immutable-byte-family rejection; source write-method spelling is also rejected before typed admission. Capability/resource entry closure remains outside B6. Schema-6 native preparation does not itself change installed descriptor or selected runtime identity.

Pure-library schema-6 closure additionally validates canonical str/bytes iteration guards (`iteration_check` with one i64 limit and Unit result), str-only `text_ord`, and scalar integer/Bool/Unit rendering casts to canonical str. Counted range comprehensions retain native unsigned capacity lowering: i64-to-u64 casts, u64 additions and i64/u64 list acquisition capacities. These are structural typed forms, not host body decisions; source evaluation order, comprehension bindings and name shadowing remain producer-owned. Mutable buffer iteration and other numeric/text operations remain outside this admission.

Body logical values admit at most 2,097,152 postorder rows, including canonical comparison and owned cloning. Syntax and other component profiles retain 1,048,576 rows. The 64 MiB wire, 4,194,304 edges and decoder visits, 512 MiB decoder allocation budget, depth 256 and typed-table limits remain unchanged. Body readers admit existing eight-field typed.Record schemas; syntax readers retain seven fields, and decoded records must match the requested DTO exactly.

Canonical str and immutable bytes repetition lowers through a bounded gathered List of the same element identity and an empty-separator join. Join requires one exact List[receiver] argument and the same canonical receiver/result type; mutable byte buffers, foreign elements/results and other arities are refused.

Schema 7 keeps the complete named-value DTO unchanged and adds closed entry resource graph admission. Primitive Filesystem/Stream/file/text_file IDs come from the authenticated native type ABI; they do not authorize user resource layouts or capability collections. Open demands canonical List[str] before Result[file|text_file,str]; only that Result recipe can carry a file primitive. Open has three operands (Filesystem, str path, str mode), a finite native mode letter and exact text flag/handle result. Read uses a scoped file local, optional i64 count and exact canonical bytes/str result. Stream write and print retain exact operand, arity and output metadata.

A file `with_scope` must join its raw statement and binding, contain a file-typed resource, readonly scoped-file local and matching body termination. Final local initialized flags may be false after native branch-flow merging; initialization is established by the with binding, while final metadata remains part of exact shadow comparison. A bounded topological traversal proves that every file method is dominated on **every** typed graph path by its unique binding's body. Nodes shared outside or between sibling scopes fail closed. Handle-valued operands may feed only the enclosing with resource; file parameters, returns, ordinary stores and handle collections are refused. Scope depth is bounded at 256 and typed graph edges at 4,194,304. Native entry/effect checks and Core cleanup insertion remain explicitly retained; arbitrary resources and unrelated file methods remain outside this profile. Schema 6 replies cannot be admitted as schema 7.

Schema 7 native admission is restricted to binary read-only `open(..., "rb")` and binary `read`. Authentic text and writable open graphs are outside this profile and are rejected before adoption; their eventual source semantics require a separately qualified extension.
