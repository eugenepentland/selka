# Interface files

`selka api` makes a module's public interface a small generated text file, checked in beside the source. A reviewer sees
an interface change as an ordinary diff, and an edit that only touches bodies never touches the file.

## `selka api`

Every project module gets one file beside its source, with `.api` in place of `.selka`: `shop/billing.selka` gets
`shop/billing.api`. Embedded standard modules and test modules (`*_test.selka`) get none.

```console
$ selka api examples/interface-files/main.selka --write
api: wrote shop/money.api (shop.money)
api: wrote shop/billing.api (shop.billing)
api: wrote main.api (main)
api: 3 interface files current (3 written, 0 deleted)
$ selka api examples/interface-files/main.selka --check
api: 3 interface files current
```

| Option | Meaning |
| --- | --- |
| `--write` | Write every missing or stale file, leave current ones untouched, and delete orphaned ones. |
| `--check` | Write nothing. Exit 1 when any file is missing, stale or orphaned, and show what changed. |
| `--json` | Print one `interface-files-v1` JSON object instead of the text report. |

Exactly one of `--write` and `--check` is required.

| Exit | Meaning |
| --- | --- |
| 0 | Every file is current (`--check`), or the files were written (`--write`) |
| 1 | `--check` found a missing, stale or orphaned file; or a declaration does not resolve |
| 2 | Usage error, or an interface file that cannot be read, written or deleted |

The command reads declarations only and never checks bodies, so it runs in the middle of a change.

## What the file contains

`examples/interface-files/shop/billing.api`, generated from `shop/billing.selka`:

```console
$ cat examples/interface-files/shop/billing.api
# generated by selka api; do not edit
module shop.billing
"""Invoices and their totals."""

public const TAX_PERCENT: int = 8

public record Line:
    quantity: int
    unit_cents: int

@ensures(result >= 0)
public func total(lines: Line[], named taxed: bool = True) -> int

public func charge(lines: Line[]) -> shop.money.Cents
```

The file is Selka declaration syntax without bodies:

- the header line, the `module` line and the first paragraph of the module docstring;
- every public declaration, in source order: records, unions, enums and results with their fields and cases; resources;
  type aliases; `const` declarations with type and value; re-exports as `export module.Name`;
- each public function's whole signature: type parameters and requirements, `mut` and `named` markers, defaults, the
  return type and the `fails` type;
- the `@deprecated`, `@requires`, `@ensures` and `@invariant` clauses above a declaration, as written, with whitespace
  runs folded to one space ([contracts](../contracts.md#reports-interfaces-and-caches)).

The module docstring goes after the imports and before the first declaration. A `"""docstring"""` above the `import`
lines is `E_SYNTAX`.

```selka
# doc: expect 42
import strings

"""Invoices and their totals."""

public func total(lines: int[]) -> int:
    return sum(lines) + strings.char_count("")

func main() -> int:
    return total([40, 2])
```

Types are written canonically: aliases are expanded, capabilities use their Python spelling (`Stream`, `Filesystem`), the
module's own declarations are unqualified, and every other declaration is qualified by its full module name
(`shop.money.Cents`, not the import alias).

Nothing is inferred from a function body. The file stays byte-identical when an edit changes only a function body, a
private declaration, a comment or a declaration's own docstring, or the layout of a signature.

## Checking and reviewing a change

`--check` lists each out-of-date file with a unified diff to the regenerated one (at most 40 lines per module), then the
command to run:

```console
$ selka api main.selka --check
api: app is stale (app.api)
--- app.api
+++ app.api (generated)
@@ -2,3 +2,3 @@
 module app
 
-public func compute(value: int) -> int
+public func compute(value: int, extra: int = 1) -> int
api: 1 interface files out of date; run `selka api main.selka --write`
$ selka api main.selka --check --json
{"version":"interface-files-v1","mode":"check","status":"stale","files":2,"modules":[{"module":"app","path":"app.api","state":"stale","added":[],"removed":[],"changed":["compute"]}]}
```

In the JSON report, `state` is `missing`, `stale` or `orphaned`. The `added`, `removed` and `changed` lists name
declarations (`Domain.member` for a qualified one, `__doc__` for the module docstring), so an orchestrator can see which
callers a change may affect.

An orphan is a `.api` file under the entry's directory (hidden directories and `zig-out` are not searched) whose `.selka`
source no longer exists and that still starts with the generated header. `--write` deletes it. A file without the header
(written by hand), and one whose source still exists but is not loaded from this entry, are never touched.

## Enforcing current files with `selka.json`

A project opts in by setting `interface_files` in its [`selka.json`](import-policy.md#configuration-shape):

```json
{"version": 1, "interface_files": true}
```

Then, once the project's bodies check, `check`, `check-project`, `run`, `run-project` and `build` reject a missing or
stale interface file:

```console
$ selka check main.selka
app.api:1:1: error[E_INTERFACE_FILE_STALE]: the interface file of module `app` is stale; run `selka api main.selka --write` and review its diff
```

The key must be `true` or `false`; leaving it out means `false`. `selka test` checks the project as `check` does, so a
stale file fails a test run too (a test module itself needs no file). `index-project`, `context`, `list-interfaces` and
`lint` do not enforce the files. An application that imports a locked
[package](packages.md#symbolic-links-repeated-warnings-and-interface-files) writes its files with
`selka packages build ... --command api -- --write`; the package's modules need none there. `examples/interface-files`
is a project with the key set and its files checked in.

## Relation to `api-diff`

[`selka api-diff`](api-diff.md) classifies a change against a recorded baseline of declaration fingerprints. Interface
files are that baseline as readable text, kept in version control. They add the first paragraph of the module docstring,
which the fingerprint does not include.

## Public release baselines and decisions

A public release baseline uses the `api-diff` fingerprint format, restricted to public declarations. Making a
declaration public is an addition; making it private is a removal. Body-only changes need no decision. The `E_RELEASE_*`
findings are in [release-docs](release-docs.md#diagnostics).
