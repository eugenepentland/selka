# Interface files

When many people or agents change one codebase, a change to a module's public
interface is the signal that other code is affected. `mylang api` makes that
interface a small generated text file checked in beside each module source, so
a reviewer sees an interface change as an ordinary diff, and an edit that only
touches bodies never touches the file.

## `mylang api`

Every project module gets one file beside its source, with `.api` in place of
`.my`: `shop/billing.my` gets `shop/billing.api`. Embedded standard modules get
none.

```console
$ mylang api examples/interface-files/main.my --write
api: wrote shop/money.api (shop.money)
api: wrote shop/billing.api (shop.billing)
api: wrote main.api (main)
api: 3 interface files current (3 written, 0 deleted)
$ mylang api examples/interface-files/main.my --check
api: 3 interface files current
```

| Option | Meaning |
| --- | --- |
| `--write` | Write every missing or stale file, leave current ones untouched, and delete orphaned ones. |
| `--check` | Write nothing. Exit 1 when any file is missing, stale or orphaned, and show what changed. |
| `--json` | Print one `interface-files-v1` JSON object instead of the text report. |

Exactly one of `--write` and `--check` is required.

| Exit | Meaning |
| --- | --- |
| 0 | Every file is current (`--check`), or the files were written (`--write`) |
| 1 | `--check` found a missing, stale or orphaned file; or a declaration does not resolve |
| 2 | Usage error, or an interface file that cannot be read, written or deleted |

The command reads declarations only. Bodies are never checked, so it runs in
the middle of a change just as `list-interfaces` does.

## What the file contains

Here is `examples/interface-files/shop/billing.api`, generated from
`shop/billing.my`:

```console
$ cat examples/interface-files/shop/billing.api
# generated by mylang api; do not edit
module shop.billing
"""Invoices and their totals."""

public const TAX_PERCENT: int = 8

public record Line:
    quantity: int
    unit_cents: int

@ensures(result >= 0)
public def total(lines: list[Line], *, taxed: bool = True) -> int ceiling(managed_allocation)

public def charge(lines: list[Line]) -> shop.money.Cents ceiling(managed_allocation)
```

The file is mylang declaration syntax without bodies:

- the header line, the `module` line and the first paragraph of the module
  docstring;
- every public declaration, in source order, one block each: records, classes,
  unions, enums and results with their fields and cases; domains with their
  codec and their public members nested beneath them; resources; type aliases;
  named constraints; `const` declarations with their type and value;
  re-exports as `export module.Name`;
- each public function's whole signature: type parameters and their
  requirements, `mut` markers, the keyword-only `*`, defaults, the return type,
  any `noalloc`, `noio` or `effects(...)` clause as written, and the
  `ceiling(...)` that `list-interfaces` publishes (the effects the parameters
  permit, narrowed by that clause);
- the `@deprecated`, `@requires`, `@ensures` and `@invariant` clauses above a
  declaration, as written, with runs of whitespace folded to one space
  ([contracts](../contracts.md#reports-interfaces-and-caches)).

Types are written canonically. Aliases are expanded, capabilities use their
Python spelling (`Stream`, `Filesystem`), the module's own declarations are
unqualified, and every other declaration is qualified by its full module name
(`shop.money.Cents`, not the local import alias).

Everything the file shows comes from the declaration index. Nothing is inferred
from a function body. The file stays byte-identical when an edit changes only:

- a function body;
- a private declaration;
- a comment or a declaration's own docstring;
- the layout of a signature.

The same sources always render the same bytes, whether the cache is cold, warm
or disabled.

## Checking and reviewing a change

`--check` lists each out-of-date file with a unified diff from the checked-in
file to the regenerated one (at most 40 lines per module), then the command to
run:

```console
$ mylang api main.my --check
api: app is stale (app.api)
--- app.api
+++ app.api (generated)
@@ -2,3 +2,3 @@
 module app
 
-public def compute(value: int) -> int ceiling(managed_allocation)
+public def compute(value: int, extra: int = 1) -> int ceiling(managed_allocation)
api: 1 interface files out of date; run `mylang api main.my --write`
$ mylang api main.my --check --json
{"version":"interface-files-v1","mode":"check","status":"stale","files":2,"modules":[{"module":"app","path":"app.api","state":"stale","added":[],"removed":[],"changed":["compute"]}]}
```

In the JSON report, `state` is `missing`, `stale` or `orphaned`. The `added`,
`removed` and `changed` lists name declarations: a domain member is
`Domain.member`, and the module docstring is `__doc__`. An orchestrator can read
them to see which callers a change may affect.

An orphan is a `.api` file under the entry's directory (hidden directories
and `zig-out` are not searched) whose `.my` source no longer exists and that
still starts with the generated header. `--write` deletes
it. Two kinds of file are never touched: one without the header (written by
hand), and one whose source still exists but is not loaded from this entry,
because it may belong to another entry's graph.

## Enforcing current files with `mylang.json`

A project opts in by setting `interface_files` in its
[`mylang.json`](import-policy.md#configuration-shape):

```json
{"version": 1, "interface_files": true}
```

Then, once a project's bodies check, `check`, `check-project`, `run`,
`run-project` and `build` reject a missing or stale interface file:

```console
$ mylang check main.my
app.api:1:1: error[E_INTERFACE_FILE_STALE]: the interface file of module `app` is stale; run `mylang api main.my --write` and review its diff
```

The key must be `true` or `false`, and leaving it out means `false`: nothing
changes for a project that does not set it. The bytes of every checked-in
interface file are part of the configuration identity that the verdict caches
use, so editing or deleting one never replays an earlier successful check.
Navigation and report commands (`index-project`, `context`, `list-interfaces`,
`lint`) do not enforce the files; `mylang test` checks the project the way
`check` does, so a stale file fails a test run too, and such a project's test
runs never replay a whole recorded report.
`examples/interface-files` is a project with the key set and its files checked
in.

## Relation to `api-diff`

[`mylang api-diff`](api-diff.md) classifies a change against a recorded
baseline of declaration fingerprints. Interface files are that baseline as
readable text, kept in version control. Both show only facts that belong to a
declaration's `interface_sha256`. The one addition is the module docstring's
first paragraph, which the interface files include and the fingerprint does
not.
