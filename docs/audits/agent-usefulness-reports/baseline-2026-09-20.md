## Corrections to the plan text found during reconnaissance

1. **The `E_ARITY` message is not the string the plan quotes.** Today it is
   `collection method argument count differs from its signature`, from
   `src/sema.zig:1488` (builtin spelling at `src/sema.zig:114`), not "list
   method argument count does not match its signature".
2. **D1's `a64` acceptance contradicts S1(a).** S1(a) makes `"a b".split()`
   legal, so `a64_split_noargs.my` stops being a rejection. D1 must restate
   that acceptance as "the probe is accepted and agrees with CPython", and keep
   the signature-carrying rejection for the arities that stay illegal.
3. **L1's premise does not reproduce as written.**
   `mylang lint experiments/sexpr-port/main.my --profile=agent` reports **42**
   `L_UNTESTED_EXPORT` findings, 40 of them in `sexpr/ast.my`, because the
   program contains **no test functions at all**: `main.my` imports no
   `tests.*` module, and both `lint` and `tests-for` need an entry point, so the
   `module tests.*` files are outside the checked graph.
   `mylang tests-for experiments/sexpr-port/main.my 'sexpr.ast::as_text'`
   answers `direct (0): reached-by (0):`. The honest L1 acceptance is a fixture
   whose graph really does contain tests, plus the port's before/after finding
   count reported as measured, with the reason.
4. **No C3 instrument exists.** `velocity/score.py`, `velocity/gen_project.py`
   and `velocity/solve.py` are backlog items V0–V2 and are absent, so lane C's
   C1/C2/C3 numbers in `velocity/goal.json` cannot be reproduced by a command
   today. `tests/idiom_probes.py` exists but runs `tests/fixtures/idioms` with
   recorded expectations, not the 110-probe suite with the CPython oracle.
5. `velocity/suites/idioms/manifest.json` records `binary: commit 237871a6`
   and `measured_on: 2026-09-17`, so its baseline predates the frozen binary
   here and must be regenerated when the suite's verdicts change.
6. **The port's "33 comparisons against raw byte codes" is understated.** The
   measured count in `experiments/sexpr-port/sexpr/tokenizer.my` and
   `experiments/sexpr-port/sexpr/parser.my` is **63** equality comparisons
   against a printable byte code (≥ 32), of which **29** are against ASCII
   letter codes such as `109` (`m`). Five more compare against `10` (newline).
   The S1(b) acceptance should quote the measured number and demonstrate
   QBE-neutrality on a representative function rather than implying all 63
   were rewritten.

## W0 probe reproductions (frozen binary, 2026-09-20)

### Incomplete-interface probe (plan §2)

Source `/tmp/w0probe/hole.my`:

```mylang
# doc: expect-error E_TYPED_HOLE
module hole

public def double(x: int) -> int effects(managed_allocation):
    return x * 2

public def unfinished(x: int) -> int:
    return todo[int]()

def main() -> int:
    return double(2)
```

- `mylang check hole.my` exits 1 with
  `hole.my:7:12: error[E_TYPED_HOLE]: unresolved implementation obligation; fill this hole before checking or execution`
  plus `note: hole.my:7:17: required result type declared here`.
- `mylang list-interfaces hole.my` exits 0 and prints:

```
# doc: not-mylang
module interfaces v1; declarations/signature visibility checked; bodies not type checked
module hole
  export function double def(x:i64)->i64 effects(filesystem,network,clock,random,environment,host,managed_allocation,output,mutation) ceiling(managed_allocation)
  export function unfinished def(x:i64)->i64 effects(filesystem,network,clock,random,environment,host,managed_allocation,output,mutation)
```

So the report is reproducible: the complete function `double` and the
incomplete `unfinished` render the *same* full effect vocabulary, which is the
conservative internal fallback, while only `double` shows its declared
`ceiling(...)`. Nothing distinguishes an inferred set from a fallback for an
unavailable analysis. This is what F1 must separate into declared ceiling,
inferred summary, and analysis status.
