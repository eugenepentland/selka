# WP-B3: QBE phi result classes

The independent zero-branch review exposed two correctness defects in QBE 1.3
phi reuse. Both are fixed by source checkpoint
`d0537d01108eda48339cb9b46abfd8510338cdea`, based on frozen ABI5/truth64 checkpoint
`790cdfb1b38a06cae3741c0c9bba724f4cf8fb77`. The fixture-input follow-up is
`e5ed9195aa8bb649a113e458b51c686e49c85e27`. This lane changes `copy.c`; the
separate `amd64/isel.c` zero-branch optimization is outside its source and receipts.

## Defect and reduction

The original, well-typed SSA has fourteen distinct `loadl` values live across a
branch, a word comparison used by `jnz`, and a long phi selecting integer 0 or 1.
QBE accepts and type-checks that input. During GVN, `phicopyref` substitutes the
word comparison for the long phi. The resulting long add consumes a word
temporary. Under register pressure the allocator writes four bytes of that
temporary to its spill slot, then the long add reads eight bytes. Stack priming
with ordinary allocated local storage makes the undefined upper half observable:
the false case returns `10986060914742001769` instead of `105`, while its branch
side effect remains correct.

The original debug dump preserves attribution: after parsing the result is
`%truth =l phi`; after GVN the long add uses `%cond`, which remains `w cnel`.
The original assembly writes `movl %ecx, 40(%rsp)` and later reads
`addq 40(%rsp), %r15`. No custom address placement or malformed SSA is involved.
The bounded reduction family uses one through twenty-four live loads: one
through thirteen pass both inputs, while fourteen through twenty-four fail both.
Fourteen is the smallest member failing in that family, not a claim of global
minimality. The reduced source, driver, raw failures, assembly and pass-stage
dumps remain in `experiments/wp-b3-qbe-phi-20260930/original-reduction/`.

The second defect reuses a prior phi with identical incoming values without
comparing result classes. A word phi choosing `-1` or `0` can replace a long phi
with the same constants; the nonzero path returns `4294967295` instead of
`18446744073709551615`.

## Correction and regression contract

`phicopyref` now requires exact result-class equality for previous-phi reuse.
Its dominating-branch substitution applies only to a `Kw` phi. It introduces no
implicit extension or new instruction-selection path. `QBE-PHI-WIDTH-1` records
the contract, and `vendor/README.md` records the local QBE change.

The executable fixture covers long and word boolean phis under pressure, a
word/long prior-phi mismatch, and valid same-class long and word reuse. Its input
values include `0`, `1`, `1 << 32`, `1 << 48` and `UINT64_MAX`; separate reuse
cases include `UINT32_MAX`. The final GVN dumps show that the long boolean phi
and both different-class phis remain, while word boolean reuse and same-class
long/word reuse still occur. All five structural checks pass in the receipt.

## Replaying the executable regressions

From a compiler checkout, build its unattached compiler and QBE with the pinned
Zig toolchain, then run the checked-in fixture and original reduction. Keep all
scratch and caches local to that checkout:

```bash
mkdir -p .tmp/phi-replay/tmp .tmp/phi-replay/global .tmp/phi-replay/local
export TMPDIR="$PWD/.tmp/phi-replay/tmp"
export ZIG_GLOBAL_CACHE_DIR="$PWD/.tmp/phi-replay/global"
export ZIG_LOCAL_CACHE_DIR="$PWD/.tmp/phi-replay/local"
scripts/build-slot.sh build zig build affected-compiler
scripts/build-slot.sh build python3 experiments/wp-b3-qbe-phi-20260930/run_phi.py .tmp/phi-replay/native zig-out/focus/qbe
scripts/build-slot.sh build python3 experiments/wp-b3-qbe-phi-20260930/run_minimal.py .tmp/phi-replay/minimal zig-out/focus/qbe
```

The developer-only Python replay scripts use the independent system C compiler.
The checked-in Zig regression uses the pinned Zig C compiler. Python does not
participate in the compiler build or guest runtime.
