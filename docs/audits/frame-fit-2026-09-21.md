# A callee's frame is sized from what its body declares — 2026-09-21

This closes the item [fixed-array-inplace-2026-09-21](fixed-array-inplace-2026-09-21.md)
left open under "Limits and what is left": passing a large `[N]T` to a function
called in a loop cost whole seconds, and none of it was the element reads. It is
the follow-up to the third row of the
[performance-parity-audit-2026-09-21](performance-parity-audit-2026-09-21.md) §3
defects. Nothing about the language surface changed; no new syntax exists.

Branch `claude/zen-darwin-3c55b9` over `fix/defects-combined` (`09579710`, the
merge of `fix/arena-chunk-reuse`, `fix/array-inplace` and `fix/dict-hash`).

## What was wrong

`Emitter.emit` in `src/qbe.zig` had to decide, before lowering a single
instruction, whether a function's frame fits the 32 KiB native-stack limit or must
be a heap block that `myl_qbe_frame_allocate` `calloc`s and `myl_qbe_frame_release`
frees on every call. `frameBytes` bounded the frame with four terms that had each
drifted away from what the lowered body carries:

* every local at its value's full size, including a parameter that
  `QBE-AGGREF-1` reads through the caller's address and whose slot only ever holds
  that address (`initializeStorage` stores `%a0` into it and nothing else);
* **twice** `temporarySize(pc)` for every pc where `usesTemporary(pc)` — the
  `%agg{pc}`/`%aux{pc}` pair — although constructor forwarding
  (`QBE-CTORFWD-1`), the borrow rule (`QBE-AGGREF-1`), the in-place array write
  (`QBE-ARRAYWRITE-1`), a scalar element read and a by-address parameter read all
  leave the pair undeclared, and `dropUnusedSlots` removes exactly those
  declarations after the fact;
* every outgoing argument at its value's full size, although `argumentType`
  passes every unmanaged aggregate as an address;
* the return type at its full size, although a result over 4 KiB crosses through
  the caller's `%out` and occupies nothing in the callee.

For `kernel(values: [1024]int)` returning `values[0]` the bound was
82,128 bytes — 8,192 for the slot, 2 × 8,192 for the `load_local` pair, 2 × 8,192
for the `get_index` pair, doubled — against a real frame of a few words. The
emitted body has no `%agg` and no `blit`; the prologue still allocated, zeroed and
freed 82 KB per call.

## What changed

**`QBE-AGGREF-9`.** `localSlotBytes` sizes a `byReference` local at one word in
both `allocateStorage` (the declaration) and `frameBytes` (the estimate);
`argumentBytes` charges one word of outgoing space for anything that crosses as a
scalar or an address and the value's size only for a move-only aggregate that
still crosses by value; the return term is `returnStorageBytes`, which is zero for
a caller-owned result. Every zero-fill, copy and release path already skipped
by-address locals, so the slot's content and use are untouched.

**`QBE-FRAMEFIT-1`.** The native-versus-heap decision is made from the scratch
the lowered body actually declares. `emit` now runs the analysis, then:

1. computes the conservative bound, `frameBytes(capacity, possibleTemporaryBytes())`;
2. lowers the function onto the native stack (`lower(name, capacity, .native)`)
   — unconditionally, because when the bound already fits this is the final text;
3. if the bound was over the limit, re-measures the frame as
   `frameBytes(capacity, declaredTemporaryBytes(text))`, where
   `declaredTemporaryBytes` sums the `%agg{pc}`/`%aux{pc}` `alloc8` lines
   that survived `dropUnusedSlots`; a frame that now fits keeps that text;
4. otherwise calls `restart(serial)` — temporary numbering, `pc`,
   `frame_offset`, `linked`, `small_leaf` and the fused-decode mark go back to
   where the discarded pass started, the analysis stays — and lowers again as
   `.{ .heap = possible }`, at the conservative size, exactly as before.

So the only functions lowered twice are the ones that genuinely need a heap frame,
and the whole program was already emitted twice (once to learn which functions
allocate). A native frame is bounded by the limit, which sits well inside the 64 KiB
headroom, so a leaf's floor guard is skipped from that fact alone (`small_leaf`);
a heap frame keeps the old `bytes + 32 < headroom` test. The `E_QBE_UNSUPPORTED`
check on `abiStackBytes` moved into the heap branch, the only place it could ever
fire.

## Limits and what is left

* **Inlined callees copy the array.** `bytecode_inline.zig` splices a small leaf
  such as `kernel(values) -> values[0]` into its caller, and the spliced
  parameter becomes a caller local the argument is `blit` into: `outer(values)
  = kernel(values) + kernel(values)` carried two 32 KiB copies and a 917 KB heap
  frame *because* the calls were inlined. The frame decision is now right for
  that shape too, but the copies are the inliner's, and a by-address splice is a
  separate change.
* **A big literal costs a word per element of operand stack.** `main` holding a
  `[1024]int` literal has an operand-stack capacity of 1,024, so its frame is
  8 KiB for the local plus 8 KiB of `%s` slots, and it lands just over the limit
  at 32,976 bytes. `main` runs once, so this costs nothing measurable.
* **A heap frame is still sized at the conservative bound.** Its slots are
  derived from `%frame_memory` at fixed offsets, so the block is not shrunk to the
  surviving scratch; a function that needs a heap frame pays the block, not its
  content.
* **Locals that survive nothing are still counted.** `frameBytes` charges every
  `%l`/`%s` slot whether or not `dropUnusedSlots` removes it; only the
  per-pc scratch is measured.
* **Only the QBE backend was measured.** The `docs/performance.md` table used to
  carry LLVM columns for the scan rows; the LLVM arm was not rebuilt here.
