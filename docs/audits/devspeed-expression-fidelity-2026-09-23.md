> **Ported to main on 2026-09-29** (branch `claude/devspeed-fidelity`, commit
> "Port devspeed/expression-fidelity"). Everything below landed except `**`
> (`PY-POW-1`): main rejects `**` by design with a hint (`PARSER-HINT-10`), so the
> power operator, its runtime helpers and its tests were left out. The list
> repetition test now states value semantics, and the comparison level sits
> below main's separate `|`/`^`/`&` levels.

Branch `devspeed/expression-fidelity`. It was cut from `base/devspeed-impl-20260923`
(`371dbd17`), then `devspeed/integration` (`243a7b62`) was merged in at `db01ecb7`.
This lane adds the cheap Python expression idioms the 23 September audit (§7, §9
item 7) lists as guaranteed repair rounds for an agent that writes Python-shaped
code. Each one follows CPython unless the language already declares a divergence.

## What changed

| Idiom | Spec tag | Behaviour |
|---|---|---|
| `f"{x:.2f}"`, `{s:>8}`, `{n:05d}`, `{x:^10.3f}`, `,`/`_`, `d b o x X n e E f F g G % s` | PY-FSTRING-SPEC-1, -2 | Byte-for-byte CPython 3.14 output for `str`, every integer width and `float`. The specification is literal, validated at check time with CPython's reasons (`E_FORMAT_STRING`), and packed into one word. The Zig formatter unit renders it into a text built at its exact size. |
| `str`/`bytes` ordering | PY-TEXT-ORDER-1 | `<` `<=` `>` `>=` compare by code point / octet with a prefix first. Mixing `str` and `bytes`, or ordering any other collection, is still `E_TEXT_OPERATOR`. |
| `range(start, stop, step)` | PY-RANGE-STEP-1 | Negative steps work in `for`, comprehensions and `list(range(...))`. The loop counts with a wrapping add and stops where the next value would leave the counter's type, so the last step never traps. A literal `0` step is `E_RANGE_STEP`; a runtime zero traps `R_ASSERT` with CPython's message before the first iteration. |
| `**` | PY-POW-1 | Right-associative, binding tighter than unary minus: `-2 ** 2` is `-4`, `2 ** 3 ** 2` is `512`. `int ** int` is exact; overflow traps `R_OVERFLOW` like `*`. A negative exponent is **rejected**: a literal one is `E_NEGATIVE_EXPONENT` and a runtime one traps `R_NEGATIVE_EXPONENT`, with the alternative `float(base) ** n`. `float ** int` uses libm `pow`, as CPython does. `float ** float` stays `E_FLOAT_OPERATION`, and its alternative names `math.sqrt`. |
| `round(x, n)` | PRELUDE-ROUND-2 | Returns a `float`. Rounds the **exact binary value** with halves away from zero, the language's declared `round` rule. `round(2.675, 2)` is `2.67` (as CPython) and `round(0.125, 2)` is `0.13` (CPython: `0.12`). The `round-half-away-from-zero` entry in `velocity/divergences.json` now carries three reproduced `round(x, n)` cases. |
| `str * int`, `int * str`, `bytes`, `list * int`, `*=` | PY-REPEAT-1 | Both operands are evaluated once, in source order. Text is joined into one exactly-sized allocation. A list repeats its elements shallowly; `xs *= n` repeats in place, so aliases see it. A count ≤ 0 gives an empty value. |
| `a < b <= c` | PY-CHAIN-1 | The six comparisons share one precedence level. Each middle operand is evaluated once, and the chain stops at the first false link. This works in ordinary bodies, generic bodies and constants. |

**How format specs relate to `strings.format_float` and `round`.** All three round
the exact binary value; only exact ties differ:

- A `.nf` specification breaks exact ties to even, as CPython's `_Py_dg_dtoa` does:
  `f"{0.125:.2f}"` is `0.12`, and `f"{-0.001:.2f}"` keeps its sign as `-0.00`.
- `round(x, n)` and `strings.format_float` break exact ties away from zero (`0.13`).
- `format_float` also prints `0.00` for `-0.001`.

The comparison is written up in `docs/text.md#format-specifications` and
`docs/standard-library.md`.

## Known gaps

- **Plain float interpolation still differs from CPython for very large and very small
  values.** `f"{x}"` and `f"{x:}"` render through `str(x)`, which prints them without
  an exponent: `str(1e16)` is `10000000000000000.0`, where CPython gives `1e+16`. A
  non-empty specification without a type, such as `f"{x:>10}"`, already uses CPython's
  `repr` digits. Making `str(float)` repr-shaped is a separate, wider change.
- **Rejected on purpose, each with a message:**
  - the `c` type;
  - a nested `{...}` inside a specification, which is how CPython writes a computed width;
  - fractional-digit grouping (`.4,f`, new in 3.14);
  - `bool` values, where CPython would format `True` as `1`.
- `n` uses the C locale (it behaves as `d`/`g`), which is CPython's default.
- `float ** float` and a negative integer exponent are rejected, not converted to float.

## Integrator notes

- **The integration line split `sema.zig`.**
  - This lane's checker logic lives in the new `sema_idioms.zig`.
  - The existing files only gained call sites: `sema_operators.binaryValue`, the chain
    hooks in `sema_expressions`, `rangeStep` in `sema_loops`/`sema_collections`,
