   - **A native SHA-256 (F-S1B-A-10).** `hashes.sha256`, written in Selka, hashes the reviewed PDFs and takes 27-40% of `check`.
     Implement it in the C runtime behind the same library function, using the CPU's SHA extensions where present, and check it
     against the existing digests.
   - **The design is copied per sub-block (F-S1B-A-11).** `req_check_dispatch.walk_instances` builds each child's `Scope` with
     `block=copy(sb.block)` and `parent=Some(copy(scope))`. The parent scope holds the parent block, so the whole design is
     copied at every level, 33-48% of `check`. Zig passes pointers. Two fixes:
     - in the port, `Scope` becomes path-based: 18 sites in four files;
     - in the language, let a borrowed record hold `Some(...)` of the caller's borrowed record, which is the language item below.
   - **A language item, proposed, for the user to decide:** stack-nested borrowed contexts. A record built from borrows (1A) may
     also hold `Some(borrowed record)` of a parameter, so a recursive walk can pass `Scope(block=sb.block, parent=Some(scope))`
     with no copy. It is sound because each frame lives inside its caller's call. Add `W_COPY_IN_RECURSION` too: a copy of a
     parameter or its field passed into a recursive call copies the caller's context at every level, and the warning names the
     borrowed or path form.
