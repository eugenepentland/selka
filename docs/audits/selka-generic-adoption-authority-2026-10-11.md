# Schema 11 generic adoption authority

The selected function table consists of the complete ordinary declaration prefix
followed by concrete instances in producer discovery order. Native validation
joins each function's declaration span to the raw declaration ordinal; executable
IDs are never interpreted as raw ordinals. This same join protects scoped-file
ownership when an unused generic declaration precedes an ordinary function.

The identity validator authenticates ordered type IDs, parallel nullable constant
lengths, canonical instance names, requirement roles, unique keys, and the
ordinary prefix. Every added instance must be called by a preceding executable
function. A self-recursive call alone cannot authorize an extra function.

After selected recipes materialize and the whole typed batch validates, adoption
restores the native instance registry and ordinary mapping with precisely these
keys and executable IDs. Substituted parameter and return signatures are checked
using retained native signature substitution. This operation does not check a
native expression, statement, or function body, and does not manufacture native
specialization fingerprints for the selected bodies.

Authentication snapshots complete catalog records, nominal graph nodes, runtime
identity rows, name mappings, and type-to-semantic mappings. It rejects changes
to any of these tables or mappings, including changes that preserve table length.
Lookup memoization is permitted only when it leaves this semantic authority
unchanged. Source diagnostics produced while authenticating a forged signature
are removed and the reply is rejected as a component protocol violation.

Native common-phase symbolic-template checking remains retained. The current
concrete producer profile cannot replace that universal validity proof. Composite
signature substitution that would attach a new nominal identity to an anonymous
tuple is not exempt from the snapshot checks; authentic evidence and a separately
reviewed canonical binding are required before such a case can be admitted.

Seven focused native tests pass in Debug and ReleaseFast: ordinary/raw ordinal
separation, unsupported recursive-only demand, canonical name and constant-role
rejection, duplicate/foreign keys, unchanged native specialization, scoped-file
declaration ownership, and forged substituted parameter/return signatures. These
tests are not installed schema 11 qualification. Activation, genuine exchanges,
complete preserved inventories, and hostile reply controls remain required.
