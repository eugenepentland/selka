## Compact prefix contract

ABI4 uses `rc-v4`, `rc-v4-counting` and `rc-v4-sites`. Both active counts are
unsigned 32-bit words: owners at payload minus 24 and holds at minus 20. The
common mark at minus 16 and descriptor at minus 8 do not move. GC, arena and
immortal prefixes remain16 bytes. A counted prefix is24 bytes.

The active count pair shares an8-byte union with `uintptr_t retired_link`.
No link write occurs while a published object is live. Owner/hold drops mark
DYING only after both counts reach zero; queue and retirement paths then stop
reading counts. RETIRED slots carry a distinct DYING|IMMORTAL mark. A free-slot
pop reads the full link before reinitializing both counts and the common header.

The slab's first slot shifts8 bytes, from aligned metadata80 to offset88;
all strides remain multiples16, so every payload is aligned to max_align_t16.
Dedicated allocator metadata grows48 to56 bytes, preserving its old total
metadata+prefix80 bytes and aligned payload. The smaller header saves memory
only when it crosses an actual size-class boundary:8-byte payload48→32,
16-byte payload48→48,24-byte payload64→48. Zeroing writes complete16-byte
payload units plus the exact tail; rounding the tail would corrupt the next
slot's count pair. Extent lookup, grow, visits, teardown and budget charges
use the new offsets consistently.

`qbe_rc_prefix` owns the generated widths/max/offsets. Generated retention,
publication and loans now check capacity before output or history mutation.
Whole-value glue uses a conservative number of disjoint pointer words to
admit its fast path, then the existing exact transaction near saturation;
repeated aliases therefore cannot wrap halfway through an aggregate. Loan
C glue returns success so its IL caller maps count refusal as a located trap.

## Owner, hold and uniqueness census

| Boundary | O/H rule and entry points |
|---|---|
| Primitive count operations | native_rc owner_acquire/edge_release; hold_acquire/release; pin_acquire/release; native_rc_internal owner_take/drop/hold_drop |
| Receiver scope journals | native_rc_scope capture/capture_cold, scope_hold/pin, prepare/prepare_loan; pins restore all prior bits before any hold drops |
| Shape walks | native_rc_walk POINTER drops O; HOLD_POINTER and unloan drops H; shallow, flat and iterative paths preserve token role |
| Native inline values | native_rc_values flat_transfer/retain acquire O; flat_loan/native_loan acquire H with rollback; flat_unloan/native_unloan return H |
| General transfers | native_rc_transfer transfer_hold, transfer_leaf, loan_copy, box_detach_held, unique_held and held replacement keep H tokens through cloning/rollback |
| Generated C/IL | rc_glue loan/unloan/retain/drop, qbe_rc_glue increments/releases; frame journal LOAN16 and HOLD_POINTER8 release their original role |
| Views and borrows | qbe_rc_views/holds create held identity; qbe_rc_loans and aggregate/frame lowering lease temporaries; runtime retains storage for list/dictionary iterators and projections |
| Held containers/backings | qbe_runtime_rc hold_storage anchors list storage, dictionary entries/storage/index; runtime collections/dictionaries delegate slot transfer to native_rc_* |
| Uniqueness | native_rc unique, native_rc_internal unique_payload and allocator extend test O<=1 independent of H; qbe_rc_glue uniqueFast and qbe_rc_element_take mirror O and mark tests |

A mechanical one-count collapse is unsound. A live view may hold H while the
owner mutates in place, and an ownerless held payload (O0,H1) must stay alive
and remain physically unique. Receiver pins also need a lifetime token while
source edges are detached. One total count cannot distinguish (O1,H1) from
(O2,H0), although the former is unique and the latter requires a snapshot.
Removing the remaining H operations needs stronger static lifetime proofs or
an equivalent side representation of H/uniqueness; moving H into O changes
semantics and copying. This phase retains two narrowed counts. One-count work
remains a separate proof obligation rather than a claimed completed change.
