The full frozen coordinator Lox directory was copied into private baseline/candidate snapshots. `frozen-source-manifest.json` and `overlay-receipt.json` assert C1 stayed unchanged. In the fresh-construction arm only `heap.my` and `interpreter.my` differ from C1; five new tests and one counter probe are additional private files. No coordinator or production source was edited. The accepted changes are supplied as `heap.my.patch` and `interpreter.my.patch`. Getter shaping is a separate baseline-derived arm supplied as `getters-only-heap.my.patch`.

`heap.allocate_call_env(mut rt,enclosing,slot_count,args,count)` validates the argument/slot span, calls the existing reserve/GC path with the same `32 + 16 * max(slot_count,0)` charge, fills a fresh owned environment directly from the rooted value stack, then publishes it once. The callee and arguments remain stack roots; the enclosing environment is reachable through the callee or the temporary initializer environment root. Only `enter_function` changes: the same arity check and depth check run in the same order, followed by the fresh constructor. Other environment construction and writes stay as C1.

Fresh-construction candidate: **98 tests passed, zero failed/cached/skipped**. Five new regressions cover object-argument/enclosing roots across stress collection and exact byte charging, empty argument rows and freed-slot reuse, closures/bound methods/initializers under stress, wrong arity, and arity-error precedence at the recursion boundary. An initial new fixture used 63 recursion steps although `MAX_DEPTH` is 63; frozen C1 also reported stack overflow before that fixture could reach its wrong-arity call. The corrected fixture uses 62 steps, and the complete 98-test suite passed. The first failed fixture output and C1 diagnostic are preserved; no production bug was hidden.

Getter-only candidate: **93 tests passed, zero failed/cached/skipped**. Its only source change is moving the wildcard assertions in `env_slot`, `env_enclosing`, and `tree_function_obj` after their match, retaining each assertion/fallback.

Counter probe: 1,000 fresh environments, 8 slots each, 4 arguments. Both arms print `True True True True`, have 0 list copies, 0 runtime retains/releases and 0 live bytes at exit. Both `object::new_env` rows show 1,000 allocations/160,000 bytes. The fresh arm removes 4,000 calls to `heap::set_env_slot`, replacing them with 1,000 `heap::allocate_call_env` calls. Overall 1028/169,792 versus1029/169,888 allocations/bytes differ only by the old arm's extra command-line argument setup. **No heap-allocation reduction is claimed.** Raw counters/functions are preserved in `counter-summary.json` and the two raw counter files.

Native inspection (`native-symbols.json`, extracted asm): C1 `enter_function` is 996 bytes and calls `set_env_slot` inside its argument loop. The fresh arm's function is 1,332 bytes, has no `set_env_slot` call, and inlines the constructor with direct owned slot filling. The baseline setter addresses 56-byte inline Obj entries, performs exchange/restore and calls owned-drop helpers; it does not perform a per-argument malloc. The precise prospective benefit is removing those repeated validation/exchange/restore calls, with a 336-byte native function-size increase; no runtime improvement is claimed before timing.

Independently, native C1 retains getter symbols `env_slot` 278 bytes, `env_enclosing` 212 bytes and `tree_function_obj` 247 bytes. The getter-only binary has none of those three reachable helper symbols, consistent with actual native inlining; its `enter_function` remains 996 bytes. This source attribution is independent of fresh argument construction. Duplicate IR branches alone were not treated as a runtime result.

Binaries, source inputs and compiler identities are in `input-identity.json`; private scratch is `.tmp/lox-eda-parity/P1/call-env-001/`.
