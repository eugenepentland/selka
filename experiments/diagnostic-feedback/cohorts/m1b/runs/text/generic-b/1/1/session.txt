**What I changed** (`project/main.my`): removed the invalid/unused generic type parameter from both functions.
- `def biggest[T: Sortable](values: list[int]) -> int:` → `def biggest(values: list[int]) -> int:`
- `def biggest_of[T: Sortable](values: list[int]) -> int:` → `def biggest_of(values: list[int]) -> int:`

`Sortable` isn't a declared constraint (`E_GENERIC_REQUIREMENT`), and since `T` appeared nowhere in either signature it could never be inferred (`E_GENERIC_INFERENCE`). Dropping the unused parameter fixes both errors without changing behavior.

**Commands and results:**
- `bin/mylang check project/main.my` → exit 0
- `bin/mylang run project/main.my -- 1 3 2` → `3` (exit 0), matching `public/expected.json`
- `bin/mylang run project/main.my -- 5 5 5` → `5` (exit 0), matching `public/expected.json`

I also spot-checked other orderings, negatives, duplicates and 32-bit boundary values (e.g. `9 1 2` → `9`, `-5 -9 -2` → `-2`, `-2147483648 2147483647 0` → `2147483647`); all print the largest value.
