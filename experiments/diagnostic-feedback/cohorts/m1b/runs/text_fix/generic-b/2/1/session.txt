Fixed.

**What changed:** In `project/main.my`, both `biggest` and its wrapper `biggest_of` were declared with a generic type parameter `[T: Sortable]`. `Sortable` is not a requirement this compiler knows, and `T` was unused (the functions operate on `list[int]`), so I removed the `[T: Sortable]` parameter from both signatures. No other changes.

**Commands and results:**
- `bin/mylang check project/main.my` → exit 0, no diagnostics (before the fix it reported `error[E_GENERIC_REQUIREMENT]: unknown requirement`).
- `bin/mylang run project/main.my -- 1 3 2` → `3` (exit 0)
- `bin/mylang run project/main.my -- 5 5 5` → `5` (exit 0)
- Also verified `-7 -2 -9` → `-2` and `9 1 2` → `9`, so ties, negatives, and the max in any position all work.
