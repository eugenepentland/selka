Fixed `project/main.my`.

**What I changed:** the two generic signatures declared an unknown requirement `Comparable` (`E_GENERIC_REQUIREMENT`) and, once that was a valid requirement (`integer`), their type parameter `T` was unused so calls failed with `E_GENERIC_INFERENCE`. I kept the generic design and made the parameter real — `def highest[T: integer](values: list[T]) -> T:` and the same for `highest_of[T: integer](values: list[T]) -> T:` — so `T` is inferred from the argument list. No other lines were touched.

**Commands and results:**
- `bin/mylang check project/main.my` → exit 0, no diagnostics
- `bin/mylang run project/main.my -- 1 3 2` → `3`
- `bin/mylang run project/main.my -- 5 5 5` → `5`

Also verified `-7 -2 -9` → `-2`, `3 1 2` → `3`, `-5 -5 -1` → `-1` (8 of 20 compiler invocations used).
