This is a prospective version of the compiler-trial preparation, analysis and strict closeout protocol. It adds exact bindings for the RC archives used by **unmeasured rebuilt reproduction guests**, including archives compiled into private `cache-rebuilt-llvm` and `cache-rebuilt-qbe` directories when a compiler prefix contains only executables. It preserves the existing checks for measured qualified ELF bytes, source maps, outputs, collector statistics, PMU coverage, build options, allocated ELF sections, paired arithmetic and archive lifecycle.

The completed alias trial is unselected. Its measured qualified ELF bytes and their qualified runtime archives were covered by the legacy guards. Its separate reproduction builds created two new runtime archives under private build caches; those paths were absent from the frozen 223 guards. Legacy strict closeout correctly rejected that trial with `RC rebuild runtime is not guarded`. This protocol does not edit old helpers, guards or receipts, and cannot retroactively establish those archives' identities during the previous measurement window. No performance rerun is part of this tooling task.

The explicit protocol marker is `lox-compiler-runtime-guards-v2`. `prepare.py` keeps the old CLI and creates a fresh work directory, builds reproduction guests through the unchanged isolated `build.py`, checks their allocated ELF sections, and copies whole-file-exact qualified guests for measurement. Before measurement it writes `preparation-inputs.json` and `runtime-bindings.json`. The latter has exactly six roles: baseline/candidate/rebuilt × LLVM/QBE. Every role names the actual ELF, manifest and runtime archive with SHA256; the rebuilt roles must agree with successful integer-status build records and backend/options/output/hash bindings. Paths come from actual manifests, rather than an assumed compiler prefix layout. Shared preinstalled archives deduplicate in the guard map while retaining all six role records.

`runtime_bindings.py` independently reconstructs the entire permitted guard inventory from the fixed helper registry, immutable base helpers, explicitly named preparation inputs, original control/qualified binaries and sidecars, original manifest runtimes, the five copied evidence directories, fixed preparation metadata, and the six actual runtime bindings. The recorded guards must equal that reconstructed map exactly. Missing, extra, changed or substituted guards and role bindings fail, even if a declared count remains the same. A declared count alone is not a certificate. Both analysis and strict closeout require this inventory, its explicit version marker, prepared metadata hashes and runtime-binding receipt hash. Legacy preparations without the marker are refused.

The base copies and original helper SHA256 values are in `base/` and `protocol-base.json`. `build.py`, `elf.py`, `closeout.py`, `archive.py` and the existing host tests remain byte-identical to the root base. `prepare.py`, `analyze.py` and `validation.py` have narrowly recorded deltas. The new family continues to reuse the original immutable audit runner and paired-math helper. Archive format remains the checked `lox-compiler-evidence-v1` object format: its existing rule that explicit guards override build-cache exclusions now retains the fresh runtime archives too. Strict closeout reports version `lox-compiler-closeout-v2` and the verified inventory size rather than claiming the old 223-guard protocol.

Use `experiments/lox-compiler-runtime-protocol-20261003/prepare.py` with the old preparation arguments for a **new** trial. Use its `analyze.py` with the old analysis arguments and its `closeout.py` with the old check/archive/verify arguments. The copied build/ELF helpers execute under the same project root and preserve the original checked backend recipes. Frozen old trials should continue to use their original helpers and retain any failure explicitly. Host fixtures exercise both bin-only/fresh-cache and preinstalled/shared-runtime layouts, missing/extra role and guard bindings, malformed/missing archives, changed helpers/archive bytes, legacy refusal and retention through archive cache exclusions. Tests create synthetic host evidence and never run a compiler, guest, benchmark or performance counter.
