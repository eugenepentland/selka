# Bytecode VM static diagnosis and rejected direct-u8 dispatch

The exact root bytecode instruction screen reports LLVM VM instructions +1.2402% over accepted84 across 13 workloads, including string equality +3.3526%. QBE VM instructions decrease 0.2574%. This stage executes no performance workload: it inspects the frozen screen's existing receipts, guest ELFs, and checked module emissions.

Two repeated LLVM differences explain almost all of the string-equality instruction increase. The primary dispatch's successful path retains its negative normalization, bounds and IP-overflow checks, and jump table. Its u8 variant adds `mov %ebx,%eax` before the indirect jump (+1 per dispatch). In OP_GET_LOCAL, the int-list operand read has the existing stride>=2 positive certificate: `cmp/jb` reaches its payload. The u8 variant retains the canonical `test/jns` negative branch before `cmp/jae` bounds, adding two instructions on its successful nonnegative operand path. The path through operand reading and IP store grows 12→14 instructions. Byte stride cannot inherit the old signed-length capacity proof.

The frozen string-equality screen input has 10,000 loop iterations, 1,280 solo local expressions and 640 equality expressions per loop. Those expressions execute 2,560 local reads and 5,120 dispatches. The two identified differences model 102,400,000 additional instructions. The actual frozen LLVM samples differ by 101,837,228, leaving a residual of −562,772 (−0.553% of the observed delta). This is a static near attribution, not an exact dynamic trace; it omits bookkeeping, startup and other optimizer/register-allocation changes. Exact input/ELF/receipt hashes and addresses are in `review.json` and the archive.

Other helpers improve rather than explain the regression: LLVM read_short shrinks 64→45 instructions and read_constant 55→42; read_byte is fully inlined in both variants, so its absent standalone body is not zero cost. Total vm::run grows 5,586→5,605 instructions with calls 486→485. QBE read_byte shrinks 67→55 and read_short 181→168; vm::run stays 8,606/440 instructions/calls. All original cast/bounds/overflow work remains represented.

A separate source copy tries direct u8 dispatch comparisons against checked compile-time `u8(chunk.OP_*)` constants. It removes the per-iteration int local and widens only the original numeric-handler argument. All 37 comparisons, handler bodies, checked opcode load, IP order, unknown-opcode continuation and operand helpers remain. Only vm.my differs from source-v3; this copy changes neither composed9376 nor the author's v3 files. Preparation v1 failed a sanity assertion expecting 36 comparisons instead of 37 before any edit/build; its unchanged baseline copy and failure receipt are retained. V2 builds successfully on both backends using immutable d14/99ad with private caches/output/TMPDIR and build slots outside reserved CPUs.

The prototype has no static benefit: LLVM vm::run remains 5,605/485 instructions/calls and QBE 8,606/440. Every inspected helper's instruction and call totals also stay unchanged. LLVM still emits the extra move before its jump table. The prototype is rejected here, with no behavior qualification or benchmark runs. Its native ELF hashes are `ac55fc4f07bdb21dfbd940168abd8d18d00a249637fe964d1fd85b1131721397` (LLVM) and `63c04806bdf9802c515437e5405f8bfc58f544890c8a34e13c5341712d8c3eb7` (QBE).

`u8-if-rejected.patch` is evidence of the rejected source shape, not an accepted overlay. `receipts.json.gz` stores complete disassembly/IL extracts, exact build commands/logs, source maps, failure receipt, prototype sidecars and vm.my. `archive.py` independently verifies every frozen ELF, source, IL, assembly, runtime-sidecar and input hash before archiving; it never launches a guest. The inspected generic IL comes from the corresponding checked QBE module emission. Newly generated LLVM IR was not inspected, and relocated guests are not claimed byte-identical. No beneficial source-only u8 rewrite is established by this stage.
