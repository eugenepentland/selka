# S4-E bounded imported LLVM bodies: draft, 2026-10-07

This is a patch plan, not an implementation or qualification claim. The packet application currently misses split/whole parity by 12–13% at both sizes. Compiler source stays unchanged while an admitted gate or compiler build runs. Implement only after the qualified S4-V source merges.

LLVM's `available_externally` linkage supplies a definition for optimization while emitting no object definition; the owning module supplies the real hidden definition. Primary reference: https://llvm.org/docs/LangRef.html#linkage-types. Use `define available_externally hidden fastcc` for imported program bodies, retaining ordinary C convention for runtime functions and externs. No IR schema or runtime ABI change is needed.

## Emission patch

1. Add an optional `imports` index slice as the seventh field of `emit_llvm.Selection`. A source unit keeps its owned `functions` slice unchanged. The entry unit keeps its current source-independent wrapper and imports no program bodies.
2. Select actual cross-unit direct callees in release, after whole-program facts, ownership and vector planning. A present per-function facts array identifies a release pipeline, including `--no-facts`; debug has an empty array. Include only bounded function bodies and their bounded reached call closure. Start with at most 512 active Core instructions per candidate, at most 32 blocks, and 2048 imported active instructions per unit. Count instructions reachable in blocks, not retired instruction-array entries. Reject externs, runtime functions and recursion expansion; canonical compiler adapters may need a separate small emitted-body allowance. Do not select unrelated functions or candidates by global IDs, source-module names, benchmark names, or measurements.
3. Traverse owned functions and active instructions in stable source/call order. Imported functions append in first-use order with a visited set. A transitive dependency that exceeds the budget remains an ordinary hidden declaration; its owning unit still supplies its object definition. Decide admission atomically per candidate so an over-budget candidate cannot partly alter a unit.
4. `ModuleState.contains` recognizes owned and imported indices. Render owned definitions first, then imported definitions in first-use order. Foreign functions use `available_externally hidden`; owned cross-unit definitions remain `hidden`, owned private definitions remain `internal`. Foreign calls never create a duplicate declaration when the imported definition is present.
5. Render imported bodies through the existing `FunctionEmitter` with their original function index/name, facts/vector plan, source path and declaration span. The unit's existing first-use tables close strings, layouts, dictionary/value/render descriptors, zero storage, site records, runtime inline helper definitions and DWARF metadata over imported bodies too. The complete resulting LLVM text is the future cache key input. LLVM then supplies accurate `inlinedAt` records and callee names without guessed Core provenance.
6. Keep generic/helper ownership and canonical symbols stable. Imports must use the same chosen canonical symbol as their real definition. If generated equality/render adapters are imported, `adapterNamed` receives the availability linkage and the local descriptor closure follows its entire body.

## Trace repair prerequisite

The retained `trap-references-01` and generic reducer prove the old compiler correctly names the originating callee, including `leaf::origin[i64]`. S3 and S4-V Core leaf inlining relabel that origin as `app::main`. Exclude `err_trace` from Core leaf eligibility; keep the intact specialization until LLVM inlining. CFG eligibility already excludes it. This one-line core-only repair avoids ambiguous source-declaration mapping and preserves the frozen IR.

## Verification and performance

- Reduced Result and multiple-specialization regressions fail before the trace correction, then compare debug/release/verify native output with the old compiler. Add multi-module returned/propagated/conversion origins and assertion/overflow frames exercised through imported bodies. Compare the exact same checked source in split and whole modes.
- Stability tests inspect imported definitions: repeat bytes exactly; debug ordinary body edits affect only the owner; release edits affect owner and units containing an imported/inlined body; non-imported ordinary edits leave other units identical; unrelated types, constants, render closures and metadata stay independent. Preserve the entry wrapper bytes across body-only edits.
- Verify object symbol tables contain only owning real program definitions, even when a body is imported into multiple callers. Compile and link multiple units using an imported aggregate sret function and a generated rendering helper.
- Measure all 46 rows at both sizes against qualified V/index ABI, old core and Zig, with exact checksums and strict paired positive finite samples. Repeat the five real two-file applications against their same-program whole LLVM build. Packet remains failed until fresh evidence clears parity; Result trace pointer/index cost must be within noise.
- Record per-unit emitted LLVM sizes/import counts on 4.8k/48k/192k synthetic projects. The fixed per-unit import budget bounds extra text, but a bound is not evidence of acceptable scale cost. Repeat body/check/line edits and imported-helper ripple; count actual changed LLVM units. S4-X must measure whole pipeline/edit-loop costs on the final emitter, not extrapolate from this draft.
- Freeze the final combined source only after performance and correctness concerns resolve. Then run explicit 64-shard core qualification, literal full old gate, full debug/release leak+verify conformance, strict 50-case package fuzz, uncontended hot rebuild and Guardian 88. No full old gate overlaps any fuzz matrix.
