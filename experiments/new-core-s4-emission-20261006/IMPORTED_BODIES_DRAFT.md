# S4-E bounded imported LLVM bodies: draft, 2026-10-07

This records the implemented policy and its outstanding qualification. The packet application previously missed split/whole parity by 12–13% at both sizes. Imported bodies are being implemented on the corrected E checkpoint while V completes qualification; final performance and gates must use the combined source. Compiler source stays unchanged while an admitted gate or compiler build runs.

LLVM's `available_externally` linkage supplies a definition for optimization while emitting no object definition; the owning module supplies the real hidden definition. Primary reference: https://llvm.org/docs/LangRef.html#linkage-types. Use `define available_externally hidden fastcc` for imported program bodies, retaining ordinary C convention for runtime functions and externs. No IR schema or runtime ABI change is needed.

## Emission patch

1. Add an optional `imports` index slice as the seventh field of `emit_llvm.Selection`. A source unit keeps its owned `functions` slice unchanged. The entry unit keeps its current source-independent wrapper and imports no program bodies.
2. Select actual cross-unit direct callees in release, after whole-program facts, ownership and vector planning. A present per-function facts array identifies a release pipeline, including `--no-facts`; debug has an empty array. Only direct calls in recorded counted or conditional loop blocks are roots, including loop headers; setup and cold dispatch are excluded. Include only bounded function bodies and their bounded reached direct-call closure. The fixed limits are 512 active Core instructions per candidate, 32 active blocks, and 2048 imported active instructions per unit. Count non-copy instructions in blocks the emitter retains, not retired instruction-array entries. Reject externs, runtime functions, generated C adapters and the entry function; recursion expansion stops at a visited function. Do not select unrelated functions or candidates by global IDs, source-module names, benchmark names, or measurements.
3. Traverse owned functions and active instructions in stable source/call order. Imported functions append in first-use order with a visited set. A transitive dependency that exceeds the budget remains an ordinary hidden declaration; its owning unit still supplies its object definition. Decide admission atomically per candidate so an over-budget candidate cannot partly alter a unit.
4. `ModuleState.contains` recognizes owned and imported indices. Render owned definitions first, then imported definitions in first-use order. Foreign functions use `available_externally hidden` and `alwaysinline`; owned cross-unit definitions remain `hidden`, owned private definitions remain `internal`, with their original attributes. Foreign calls never create a duplicate declaration when the imported definition is present. The fixed instruction and block budgets limit imported expansion. Source-exact `paired-packet-imports-01` shows supplying bodies without `alwaysinline` still leaves the decoder called in the split hot loop while the whole build inlines it; this retained failed measurement motivates the attribute.
5. Render imported bodies through the existing `FunctionEmitter` with their original function index/name, facts/vector plan, source path and declaration span. The unit's existing first-use tables close strings, layouts, dictionary/value/render descriptors, zero storage, site records, runtime inline helper definitions and DWARF metadata over imported bodies too. The complete resulting LLVM text is the future cache key input. LLVM then supplies accurate `inlinedAt` records and callee names without guessed Core provenance.
6. Keep generic/helper ownership and canonical symbols stable. Imports use the same chosen canonical symbol as their real definition. Every call or stored function reference in an imported body makes the referenced real definition hidden, even if that dependency exceeds the import budget or was originally private to the callee's source module. Generated equality/render adapters remain ordinary declarations whose owning objects and link dependencies are included.

## Trace repair prerequisite

The retained `trap-references-01` and generic reducer prove the old compiler correctly names the originating callee, including `leaf::origin[i64]`. S3 and S4-V Core leaf inlining relabel that origin as `app::main`. Commit `344b59b60` excludes `err_trace` from Core leaf eligibility and keeps intact specializations until LLVM inlining. CFG eligibility already excludes it. This core-only repair avoids ambiguous source-declaration mapping and preserves the frozen IR. Source-exact `trap-references-02` and `provenance-cases-01` reruns match the old compiler.
