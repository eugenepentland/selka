# A02 default and retirement qualification harnesses

These harness changes prepare later C2/C3 runs. They do not promote the default,
retire runtime code, or qualify the preserved nested-extension patch. Run each
bounded batch under the shared build admission wrapper, with a fresh output
directory and a complete frozen compiler installation. Record the source commit
alongside the compiler binary hash generated by the harness. Use the actual C2
or C3 artifact; do not relabel Support4 evidence.

```sh
scripts/build-slot.sh build python3 -B experiments/memory-closeout-20261012/A02/qualify_migrations.py run --compiler COMPILER --modes default --output NEW_DIRECTORY --files tests/value_semantics/calls.my
scripts/build-slot.sh build python3 -B experiments/memory-closeout-20261012/A02/qualify_additional.py --compiler COMPILER --baseline C0_COMPILER --mode default --output NEW_DIRECTORY --files test/core/b_buffer_values.my
scripts/build-slot.sh build python3 -B experiments/memory-closeout-20261012/A02/list_methods.py --compiler COMPILER --ownership default --output NEW_DIRECTORY
```

`default` emits no ownership-selection flag. It requires the same RC-zero,
normal-return live-byte-zero and LLVM/symbol audits as explicit `zero` mode.
`ordinary` in the 51-fixture harness is solely a historical semantics control;
it also omits the flag but does not assert ownership mode. Use `default` for
promotion/retirement evidence. `check` is source admission only and never
substitutes for a counted native run.

The harnesses reject nonempty output directories, record requested files/modes
before work, preserve failing cases, write `complete` and `qualified` separately,
and return nonzero when any requested case fails. Compiler and source identity are checked
again at completion. Each result records the harness and shared audit module
hashes. Missing normal-return counters cannot pass qualification.

RC checks sum retain/release/uniqueness sites and native retain/release/share
totals only as a zero/nonzero guard: instrumentation layers may overlap, so the
sum is not a count of distinct operations. Historical `release_unique` sites
represent direct destruction in checked-ownership mode and are reported
separately. A09 confirmed that C3 retains this telemetry distinction. LLVM and
linked-symbol checks reject known RC helpers and legacy count-access patterns;
the final source/header/preprocessor/layout audit remains A07/A10's separate
requirement.

For the six additional guest-test fixtures, the harness keeps the actual guest
runner's seed-7, 12-trial property results and intentional trap expectations.
It also builds a counted contract executable from the unchanged source. For
zero-argument Boolean tests this runs every normal-return test; the four list
trap cases remain covered by the actual guest command. Byte-buffer properties
receive explicit empty/nonempty, Some/None, False and handled Ok/Err cases.
Those counters belong to the supplemental executable, not all randomized
guest workers. The A10 guest-runner ABI/cache matrix remains required.

Fatal traps compare the original diagnostic codes and structured trap metadata.
Structural RC checks still apply to their binary; available trap counters must
have zero RC events. A fatal trap is not claimed to unwind all live owners, so
normal-return live-byte-zero is reported separately.

Validation of this harness revision uses preserved Support4 artifacts as
controls, not new implementation evidence: 12 legacy controls fail the owned
audit and eight successful zero-RC controls pass. The explicit default flag
list is empty; missing counters and attempted evidence overwrite are refused.
Supplemental wrapper admission and remaining qualification status are recorded
in `raw/harness-preparation/`: all six wrappers source-admit on Support4. The
initial byte-buffer wrapper's constructor errors and corrected final source
are preserved separately. No native run of these new wrappers is claimed.
Actual C2/C3 native qualification is pending.

`source-check-script.txt` is the verbatim script captured from its scratch
directory for provenance; it is not a portable runner. The supported replay
commands are the admitted qualification harness invocations above.
