The other five rewrites have no additional emitted effect in this frozen function. This is a static ablation, independent of the rejected dispatch compiler transformations in commits `74bceceaa51c225f5a3271f2ccd710e19e2362c9` and `e7c7fc42fb1e67f0e89a0a542235d00baed5a337`. It changes no compiler, guest source, canonical patch, frozen ELF or accepted artifact, and executes no guest, benchmark or performance counter.

Each arm preserves load opcode, width, destination and order. It removes only named single-use pointer copies and changes their load address to the exact original scratch allocation. The selected input has 236 direct full-word stores and 236 direct full-word loads of `%s1`, plus the single alias and its full-word consumer. Actual pinned-QBE `-d MG` dumps show that the control retains `%s1 =l alloc8 8` after slot promotion. The one-s1 arm instead turns its 236 stores into scalar assignments and its 237 loads into scalar copies. `vendor/qbe/mem.c`'s `promote` admits only direct, uniform load/store uses; the one address copy blocks that pass before later copy/load elimination. Although the control's later load-elimination pass already replaces `%v6511` with the stored value, it leaves the scratch cell allocated. Promotion has already run.

Promotion also prevents aggregate pointers carried in `%s1` from being classified as stored, escaped pointers. The unchanged alias analysis marks stored pointer values as escaping, while slot coalescing can remove or fuse private buffers once those uses become scalar assignments. The actual coalescing dumps leave 75 allocations totaling 3,656 bytes in the control and 37 totaling 2,888 in the one-s1 arm. After normalizing only generated SSA suffixes for comparing allocation names, 38 allocation names disappear with total size 768 bytes. This exactly matches the fixed-frame reduction, 5,528→4,760; the remaining 1,872 bytes are identical in both arms. It is a global promotion/coalescing effect, rather than the removal of one eight-byte cell alone. The explanatory `main.c`, `mem.c` and `alias.c` bytes match selected Git base `3b33df52044a10cb84b908f8b1641af439e8c729`; the pinned executable's actual pass dumps independently establish the observed pass behavior. This experiment does not reconstruct the executable's full build provenance.

`%s0` has full-word stores/loads and four byte loads through aliases. Rewriting all five addresses exposes width-one reads alongside width-eight reads/stores, which still refuses uniform slot promotion. Accordingly those five rewrites have no assembly effect here. Their unchanged byte widths remain checked; no full-word-load or masking replacement was tried.

GVN reduces bounds-failure call sites from 56 to 32 in the one-s1 arm. All 24 removed call sites target `myl_qbe_fail_normalized_index_bounds`, and 24 `ud2` sites disappear with them. These are failure branches; fewer emitted failure calls do not mean 24 fewer calls on successful execution. Whole-function differences also include 320 fewer `movq`, six more `movl`, 24 fewer `cmpq` and 16 fewer unconditional jumps. Stack move-load/store sites change 1,934→1,880 and 803→707; `lea` sites remain 249. These count static sites, not their runtime frequency.

All 37 successful dispatch walks are preserved instruction by instruction in the raw receipt. They begin at the opcode-zero comparison and stop at the original handler entry, include the original OR paths/spills/jumps, and symmetrically exclude the operand/IP prefix and handler body. Opcodes 0–15 are unchanged. Opcodes 16–36 save one stack-store instruction each in the one-s1/all-six assembly. No successful call is removed in this bounded dispatch interval. Full handler execution is not modeled because its calls, operand values and branches depend on program state.
