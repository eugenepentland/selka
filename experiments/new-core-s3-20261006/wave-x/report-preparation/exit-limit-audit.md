## Shared frontend limits still binding on new Core programs

These preserve the current language/frontend contract; they are not newly introduced S3 defects.

- **Function values/callbacks:** at most 16 value parameters (`src/callables.zig:100`). A function used as a value must be a nongeneric free function, and cannot have a `mut` record/fixed-array parameter (`src/sema_calls.zig:160–168`). A lambda has the corresponding mut record/array restriction (`src/sema_expressions.zig:874–875`). Whole rebinding of a mut fixed-array parameter remains checker-refused; callers may write elements or copy into a local (`src/sema_places.zig:532–544`).
- **Generic declarations:** at most 16 type/const arguments and 16 combined requirements per parameter (`src/generic_requirements.zig:127,159,170,189,323`; `src/generic_instances.zig:46–48`). The instance budget is **4,096 per generic declaration**, not per whole program. Array shapes/callback signatures have a separate **4,096 per source spelling** budget (`src/type_catalog.zig:23–30,85–95`). Generic inference and generic body checking stop at 256 levels or 100,000 checking operations (`src/generic_inference.zig:25`, `src/generic_bodies.zig:174`).
- **Nominal types:** nominal expression expansion stops at 256 levels/100,000 visits (`src/nominal_templates.zig:350–360`); layout expansion has per-request 100,000 operations, 4,096 instances and 4,096 array shapes plus depth 256 (`src/nominal_layouts.zig:125–127,167–194`). Nominal argument shapes also stop at depth256 (`src/nominal_state.zig:35`). An individual display name is at most 1MiB; aggregate display-name retention is max(1MiB, source bytes), not a fixed program-wide 1MiB cap (`src/nominal_catalog.zig:104–117`).
- **Source and embeds:** headerless source/test initial reads cap at 64MiB (`src/core/frontend.zig:46`, `src/core/test_runner.zig:60`). Module-headed projects load with the defaults 16,384 modules, 262,144 import edges, 4MiB per source/embedded input and 64MiB combined source/embedded bytes (`src/core/frontend.zig:75` calls `project.load(...,.{})`; `src/project.zig:55–59`). The standalone embed ceiling remains 16MiB (`src/embed.zig:24,237–240`), but the module-project 4MiB/default remaining-total budget can be tighter. The common project's options are configurable in its own API/configuration workflow; the current Core path shown here supplies `.{} ` and exposes no budget override flag.
- **Entry/test contracts:** source main accepts an optional first `args: list[str]`, then at most one of each capability family, with separate at-most-one `out` and `err` Streams; result is int, None or Result[int/None,E] with printable E (`src/sema.zig:1757–1777,1992–1997`). Tests require bool or Result[bool,E]; other returns are `unsupported`, absent a broader cases-file workflow (`src/core/test_runner.zig:110,123`). The manual IR emitter's narrower raw Result entry checks are not an additional source-main restriction: the shared checked entry adapter builds an integer-returning wrapper (`src/entry_adapter.zig:51–121`).

## Corrections to inherited S2 implementation-limit wording

- S2's general split still materializes owned pieces/list, but the qualified A source adds a **private whitespace-split dictionary-key loop** fusion. It requires exact compiler runtime authority and all-use/dominance checks; escaped pieces, retained lists, other consumers and phis fall back to materialization (`A src/core/fuse_text_split.zig:16–18,76–87,91–110,124–140`; A REPORT lines94–99). This is an optimization boundary, not a language refusal. No general source/parameter SSA-view ABI or short-string representation was added.
- Char `3f47456ce` similarly removes temporary one-scalar strings only when **every use** is eligible literal scalar equality or a disjoint character append; other consumers/escapes/phis retain the materialized implementation (`src/core/fuse_text_scalar.zig:20–55`). Unicode falls back from the guarded ASCII emitter to the existing runtime helper. Do not describe all character expressions as allocation-free.
- The preparation's sentence "User modules/interfaces ... are S4" is too broad if read as a blanket module-source refusal: current `src/core/frontend.zig:54,75–92` loads module-headed projects, builds the ordinary interfaces and checks merged whole-program source. S4 still owes the new Core's persisted per-module/interface/cache/incremental workflow and Lox/EDA qualification; existing fresh merged-source module loading is already present. Keep the seven flattened coverage-context failures as failures of that sweep context, not proof every valid user module is unsupported.

No additional limit was inferred from optimization-only ceilings (five-step packed field paths, four register words before indirect aggregate passing, stack-promotion4096 bytes): those have ordinary lowering/fallback paths and are not source admission limits. No new qualification claim is made for source programs outside the retained corpus.
