# Full-tool discovery audit and retained guard RED

This package precedes any production correction. It contains a successful
actual corrected M Debug build, runtime-C and final-link descendant traces,
comparison against the current 20,907-input inventory, official printed-version
primary source, and an owned reducer proving an omitted subsequently read input.
The conservative implementation proposal is in `GUARD_CORRECTION_PROPOSAL.md`.
No compiler/helper/source/flag/cache-eligibility change is part of this audit.

`summary.json` binds the protected M compiler SHA, command status, actual guest
status 7, full-trace hash and private artifact paths. `runtime-c.json` and
`program-link.json` preserve native argv; their raw descendant traces retain
successful reads, failed lookups, enumeration, metadata, readlinks and processes.
The original 128 MB trace remains task-owned private evidence and is excluded
from this curated Git package; its two native subtrees are retained here.
The corrected M binary and copied approved Zig/lib trees remain private and
are never staged. Normal build-slot admission excluded CPUs 2,3,10,11.
Helper-only analysis used CPUs 0,1,4-9,12-19.

`path-guard-summary.json` and the per-action `*-path-guards.json` distinguish
direct file snapshots, directory membership guards, unguarded discovery, tool
alias traversal, owned input/output/CWD traversal, process-local views, entropy
and generated staging. The decoded existing hint is a path comparison source;
the Python reader does not verify its opaque BLAKE3 checksum. No trust derives
from this decoder. `*-unguarded-snapshots.json` is explicitly post-probe state,
not a source-race proof. `generated-staging-provenance.json` preserves actual
exclusive creation/producer/rename events; a `/tmp` or cache prefix alone does
not justify exclusion from an input inventory.

`guard-red-summary.json` is a real unchanged-production-helper counterexample:
approved copied executable+adjacent library remain cacheable, unchanged returns
true, and both digest and generation are equal after an outside resource file
is created. The subsequent fresh native action reads that file. The emitted
object remains byte-identical; the RED is missing guard/key completeness, not
an asserted changed-output defect. Commands, actual helper/platform/input/output
hashes, standalone probe source, and successful resource read are retained.
Only task-owned copies were changed; no installed/system input was modified.

`upstream-source-manifest.json` records official llvmorg-22.1.8 URLs and hashes.
The actual linked Clang reports that version; the tag-to-pinned-binary build
relation remains unestablished. Local Zig Git-object excerpts from distribution
revision 5ceec001b5 are retained in the companion action-closure package.
Conservative fixed-layout approval/refusal must preserve this proof limit.
The existing full helper is the conservative starting point, with an unresolved
discovery closure gap; final M/cache qualification cannot rely on completeness
until a reviewed correction passes its source and inherited gates.

`extract-02.log` retains the analyzer's missing `object` receipt-field error;
`extract-03.log` is the corrected parse. `classify-05.log` retains initial broad
classification that counted owned CWD/parent traversal as external discovery;
`classify-06.log` separates those roles using actual command/producer evidence.
Neither analysis repair hides a compiler/native correctness failure. Guardian
qualification is recorded separately when this evidence package is committed.
