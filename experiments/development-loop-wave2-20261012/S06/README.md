# S06 live cache correctness matrix

This evidence uses actual production verification dispatch, registry export, artifact writer, producer authentication, provider snapshots, admission and private success stores. The native cohort contains four registered required actions: real scalar Zig tests, real tooling Zig tests, dynamic Python fixture membership, and Zig formatting. It is a bounded native cohort, not the repository gate.

`native-v4` freezes B0 `c1857310e0bf623545380c8de24515f1b9970021` with discovered namespace `verification-v1`. This does not directly qualify the later canonical verification-v2 candidate. The support artifacts in its manifest are authenticated read-only previous integration artifacts; only the two newly built native test artifacts are consumed by the selected native actions. No full compiler build is represented by this cohort.

`live_native_matrix.py` creates disposable source copies and uses the production retained `cache_session.py` entry point. It checks cold/warm decisions, real embedded grammar oracle failure and repeated failure, an added failing test, a helper semantic failure, membership addition/rename/deletion, fixture cached-pass to failure and repeated failure, exact source reverts, and a compatible independent second source tree. It never edits receipts or removes root/environment identity. Independent-tree shared reuse remains deliberately unavailable. Exact native artifact bytes may differ after source reverts; conservative execution is valid and is recorded rather than erasing implementation identity.

The archived `native-v4/harness-at-launch` records the harness and fixture template used by the running B0 experiment. A resumed invocation continues the fully captured oracle-revert checkpoint after correcting an initially overstrict reuse expectation; original reports remain archived. Startup preparation attempts before v4 failed before useful native matrix execution and are not counted as correctness cases.

`live_guest_matrix.py` runs the actual frozen installed compiler against real guest files and embedded assets. Its strict S01 supported adapter records exact selected test identities, verdicts and cache decisions. Per-test duration and resource use remain unknown; operational action wall time includes scheduling and is not an isolated latency measurement. The repaired compiler manifest distinguishes its source and copied companion prefix from complete bootstrap qualification.

`guest-fallback-patch-request.md` records the live discovery of a private uncacheable object-lifetime bug. The current host linker-cache identity differs from the reviewed platform identity, so native receipt reuse is conservatively unavailable; this harness does not refresh trust pins. A later source candidate can be tested with `live_native_matrix.py --source-root <candidate>`, a fresh scratch/output directory, and authenticated frozen support paths. Native processes use private local Zig caches, on-disk temporary directories, the shared global Zig cache, and production admission. Shared caches are private experiment stores; no peer cache is corrupted or evicted.
